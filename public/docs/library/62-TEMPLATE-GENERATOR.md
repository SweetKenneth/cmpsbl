## 2. What Is a CMPSBL Template

### 2.1 Definition

A CMPSBL Template is a production-ready cognitive pattern that integrates with the substrate's module architecture. Templates encode:

| Component | Description |
|-----------|-------------|
| **Behavioral Logic** | Defined execution patterns and decision flows |
| **Module Configuration** | Tuned settings for specific substrate modules |
| **Integration Points** | Connection patterns for external systems |
| **Governance Context** | Compliance requirements and security boundaries |

### 2.2 Templates vs. Boilerplate

| Aspect | CMPSBL Template | Traditional Boilerplate |
|--------|-----------------|------------------------|
| **Execution** | Runs against live substrate | Requires implementation |
| **Behavior** | Encodes cognitive patterns | Provides code structure |
| **Integration** | Native to substrate modules | Requires adaptation |
| **Governance** | Inherits compliance context | Compliance is manual |
| **Value** | Time compression | Starting point |

Templates deliver working systems, not starting points.

| **Legendary** | Elite | Full-stack patterns, enterprise-grade capabilities |
| **Mythic** | Exceptional | Novel synthesis, unique capability combinations |

### 3.2 Rarity Factors

Rarity classification is determined by:

| Factor | Influence |
|--------|-----------|
| **Module Coverage** | Number of substrate modules integrated |
| **Pattern Complexity** | Sophistication of encoded behavior |
| **Integration Depth** | Richness of external system connections |
| **Governance Requirements** | Compliance and security complexity |
| **Provenance** | Uniqueness of synthesized combination |

Rarity reflects genuine system complexity, not artificial scarcity.
