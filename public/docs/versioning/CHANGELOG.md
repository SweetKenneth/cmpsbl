## Changelog Doctrine

> **If this reads like SaaS marketing, rewrite it.**

### Changelogs DESCRIBE:
- **State changes** — What the system can now do that it could not before
- **Capability stabilization** — What moved from experimental to governed
- **Closed cognitive loops** — What learning cycles completed
- **New governed surfaces** — What surfaces are now observable

### Changelogs DO NOT DESCRIBE:
- Internal algorithms or weighted formulas
- Kernel mechanics or execution paths
- HOW evolution or dreaming works — only WHAT changed in behavior
- Implementation details, API internals, or secret coefficients
