# CMPSBL® Documentation System

## Organization

This documentation system is organized into a tiered hierarchy. Each tier serves a distinct audience and purpose.

### Tier 1 — Canonical Core

Foundational specifications that define what the system is, how it governs itself, and how it protects data.

| Document | Path |
|----------|------|
| Master Architecture Specification | `01-architecture/master-architecture-spec.md` |
| Governance & Autonomy Doctrine | `02-governance/governance-autonomy-doctrine.md` |
| Security Architecture | `03-security/security-architecture.md` |
| Data & Memory Model | `04-data-memory/data-and-memory-model.md` |
| Evolution & Versioning Framework | `05-evolution-versioning/evolution-and-versioning-framework.md` |

### Tier 2 — Operations & Runtime Control

Operational handbooks for running, monitoring, deploying, and validating the system.

| Document | Path |
|----------|------|
| Observability & Telemetry Handbook | `06-observability/observability-telemetry-handbook.md` |
| Deployment & Infrastructure Manual | `07-deployment/deployment-infrastructure-manual.md` |
| Testing & Validation Matrix | `08-testing/testing-validation-matrix.md` |

### Tier 3 — Strategic & External

Documents intended for external stakeholders, API consumers, and commercial partners.

| Document | Path |
|----------|------|
| Public Whitepaper | `09-whitepaper/public-whitepaper.md` |
| API & Integration Specification | `10-api/api-integration-specification.md` |
| Licensing & Commercial Model | `11-licensing/licensing-commercial-model.md` |

### Tier 4 — Founder Safeguards

Governance and continuity documents that protect the system's purpose and integrity.

| Document | Path |
|----------|------|
| Founder Intent | `12-founder/founder-intent.md` |
| Survivability & Succession Protocol | `13-survivability/survivability-succession-protocol.md` |

## Conventions

- All canonical documents follow strict section structures defined in the style guide.
- Module names are always written in ALL CAPS (e.g., NEXUS, DECODE, DEFENSE).
- Diagrams use Mermaid syntax for portability.
- Tone is neutral, technical, and OS-manual grade.
- No marketing language in Tier 1 or Tier 2 documents.
