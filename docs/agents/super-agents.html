§1The Problem With Agents Today

Most AI agent frameworks are scaffolding. They give you function calling, tool use, and a chat loop — then leave the hard problems (cost governance, memory management, multi-agent coordination, prompt injection defense, identity persistence) as exercises for the reader.

The result: agents that work in demos but collapse in production. Every team reinvents the same infrastructure — poorly. Security is an afterthought. Memory is a growing JSON file. Cost tracking is a Slack alert when the OpenAI bill spikes.

Super Agents solve this differently. Instead of wrapping your agent in more framework code, CMPSBL® collides your existing code against a 45-primitive structural matrix to discover what capabilities your agent is missing — then surgically adds them as a cognitive overlay that ships as a standalone package.

§3Phase 1–2: Ascension — The 40-Primitive Matrix

Ascension begins by classifying your uploaded code into a software archetype using weighted keyword voting across 85+ signals:

Archetype Examples Pool Size Excluded
Active Agents, bots, workers, scrapers, cron jobs 71 capabilities 22 passive-only
Passive UIs, dashboards, auth screens, static apps 55 capabilities 38 action-only
Hybrid APIs, middleware, data pipelines 93 capabilities 0 (all eligible)

Once classified, the engine performs CJPI-weighted random sampling from the filtered pool. Each capability has a baseWeight (0–100) that determines selection probability. The scoring formula — novelty, utility, complexity, composability — is proprietary and ships hex-encoded in exports.

The output of Ascension is 5 discovered capabilities, each backed by a specific primitive from the 40-primitive substrate (12 Organs, 12 Layers, 8 Engines, 8 Agents).

§6Phase 5: Tiered Persistent Memory

Every Super Agent export includes a file-backed persistent memory adapter that implements the substrate's StorageAdapter interface. Memory is organized into three active tiers:

Tier Age Storage Access Speed Strategy
● HOT < 24 hours In-memory + disk Instant Active cache, JSON formatted
● WARM 1–7 days Disk only Fast Compact JSON, promoted on access
● COLD 7–90 days Compressed (gzip) Deep recall Archived, decompressed on demand
● Expired > 90 days Auto-purged — Configurable via env variable

Memory Scoping

  • Per-agent isolation (default): Each agent stores memory in ~/.cmpsbl/memory/<agent-id>/
  • Shared memory pool: Set sharedMemory: true for cross-agent recall via ~/.cmpsbl/memory/_shared/

Zero Setup

import { createPersistentStorage } from './_runtime/persistent-memory';
import { init } from './_runtime/standalone-runtime';

const storage = createPersistentStorage({
  agentId: 'my-research-agent',
});

const instance = init({ storage });
// That's it. Your agent remembers across sessions.

The adapter uses only Node.js built-ins (fs, path, zlib). Zero external dependencies. Runs on any machine.

§10Why This Matters

  1. Discovery, not construction. You don't configure capabilities from a menu. The 45-primitive matrix discovers what your code needs through structural analysis.
  2. Deterministic, not stochastic. Same code in → same Super Agents out. Reproducible, auditable, testable.
  3. Standalone, not platform-locked. Exports run anywhere. No vendor dependency. No API keys. No recurring cost to use what you've already built.
  4. Tiered memory, not flat storage. HOT/WARM/COLD with automatic compaction and eviction — not a growing JSON file.
  5. IP-protected, not open-source-your-competitive-advantage. Black-boxed exports preserve the proprietary logic that powers discovery.

This is Governed Cognitive Infrastructure — not an agent framework. The substrate doesn't tell agents what to do. It discovers what they're missing and gives it to them as portable, standalone intelligence.
