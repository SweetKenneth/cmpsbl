## Purpose

This document describes Ascension — the proprietary evolution lifecycle where developer software enters the CMPSBL cognitive substrate and produces Ascended Memories.

---

## 1. What Is Ascension?

Ascension is the process where external developer software is introduced into the CMPSBL cognitive substrate as a Candidate Primitive. The substrate runs discovery cycles, testing interaction patterns between the developer's code and the 40-primitive matrix. Successful chains are crystallized into Ascended Memories — portable capability artifacts with structural dependencies on both the developer's code and the substrate.

---

## 2. The Four Phases

### Phase 1: INGEST

Developer software is uploaded and analyzed. The system identifies entry points, interfaces, and capability surfaces within the code.

**Upload limits (per day):**

| Plan | Limit |
|---|---|
| Builder | 0 (upgrade required) |
| Studio | 3 |
| Creator | 6 |
| Architect | 12 |

### Phase 2: ASCENSION

The ingested code operates as a Candidate Primitive within the substrate. Discovery cycles run, testing the code's interactions against all 40 substrate primitives across 4 categories.

This phase is visualized through a cinematic orbital canvas showing collision cycles between the candidate and substrate primitives.

### Phase 3: CRYSTALLIZATION

Successful interaction chains are crystallized into capability artifacts — all archetype-matched discoveries are surfaced for ascending and export regardless of CJPI score. The crystallization process follows the standard memory chain: Sampling → Condensing → Crystallizing.

### Phase 4: ASCENDED MEMORY

The resulting artifacts — Ascended Memories — are available for review and export. Each includes the full Capability Pack: implementation code, Mini Runtime, documentation, license, test bench, and manifest.

---

## 3. The Mutual Moat

Ascended Memories have structural dependencies on both components:

- **Developer's code** — The original logic and interfaces that enabled the discovery
- **Substrate primitives** — The node capabilities that interacted with the developer's code

This dual dependency creates mutual value. The developer's code gains new capabilities; the substrate's discovery record grows.

---

## 4. Recursive Ingestion

Ascended Memories can be re-ingested into the substrate for further discovery cycles. This enables compounding capability discovery:

```
Software → Ascension → Ascended Memory → Re-Ingest → Deeper Discovery → Higher-Tier Memory
```

Each cycle potentially discovers deeper interaction chains and higher-scoring capabilities.

---

## 5. Export

Ascended Memories follow the same export process as all Crystallized Memories:

- Score-gated language selection (25 targets)
- Mini Runtime bundled for standalone execution
- Full documentation suite
- Manifest with CJPI score and provenance

Export limits follow vault capacity, with no per-day caps.

---

## 6. Access

Ascension is accessed via a secured route (`/x`) with PIN authentication. This interface provides the four-phase memory chain visualization and export controls.
