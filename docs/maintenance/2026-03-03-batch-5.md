# Maintenance Engine System — Batch 5

**Date:** 2026-03-03  
**Scope:** HYGIENE, VALIDATOR, REPORTER engines + ENGINEER orchestration

## Architecture

Three new first-class maintenance engines, orchestrated by ENGINEER:

```
ENGINEER (CLM cycles)
    │
    ├── engineerTriggeredMaintenance()  ← reactive, health-gated
    │
    └── Orchestrator
         ├── HYGIENE   → retention, stale tasks, orphans, memory hygiene
         ├── VALIDATOR → GATE engine, substrate health, audit, connectivity
         └── REPORTER  → DB persistence, email, webhook, ATLAS notifications
```

## Trigger Modes

| Mode | Source | Frequency |
|------|--------|-----------|
| Manual | `runMaintenanceOrchestrator('manual')` | On demand |
| CLM | ENGINEER maintenance cycle | Reactive (health-gated, 30min cooldown) |
| Cron | `maintenance-reporter` edge function | Configurable (default daily 06:00) |

## DB Tables

- `maintenance_reports` — Persists all engine run results
- `maintenance_notification_config` — Admin-configurable notification preferences

## Notification Channels

1. **DB** — Always persists (service_role + admin read)
2. **Email** — Via `maintenance-reporter` edge function
3. **Webhook** — POST to configurable URL with optional secret
4. **ATLAS** — Substrate event system notifications

## ENGINEER Integration

- `runMaintenanceCycle()` now async — triggers `engineerTriggeredMaintenance()` non-blocking
- Records HYGIENE/VALIDATOR/REPORTER health back into ENGINEER's engine health map
- CLM study focus auto-shifts toward maintenance if engines degrade
