1. Overview

The CMPSBL Substrate provides multiple training modes that enable the Immunity Mesh to continuously learn, adapt, and harden itself against evolving threats. Training is orchestrated through the Shadow Build system and the Auto Training scheduler, both accessible from the Immunity Mesh Admin Dashboard (/admin/immunity-mesh).

2. Auto Training Mode

2.1 Purpose

Auto Training is a persistent runtime toggle that, when enabled, activates the Shadow Scheduler to automatically execute probe training cycles every 15 minutes. This provides continuous, hands-free hardening of the substrate's immune system.

2.2 Implementation

  • Toggle Location: Immunity Mesh Dashboard → Controls Tab → Auto Training Toggle
  • Persistence: State is stored in the system_flags table under key auto_training_enabled
  • Scheduler: Uses startShadowScheduler() / stopShadowScheduler() from src/lib/shadow/scheduler.ts
  • Cycle Interval: Every 15 minutes when active

2.3 Behavior

  1. Admin toggles Auto Training ON
  2. System flag is updated in the database
  3. Shadow Scheduler starts with 15-minute intervals
  4. Each cycle runs shadow probes against the immunity mesh
  5. Results are logged to immunity_probe_results and immunity_mesh_telemetry
  6. Learned rules are written to shared_rule_registry
  7. On dashboard reload, the toggle state is restored from the database flag

3. Shadow Build Modes

The Shadow Build system provides four distinct training modes, each targeting a different aspect of substrate resilience. These are triggered manually from the Shadow Build tab on the Immunity Mesh Dashboard.

3.1 Replay Tasks

AttributeDetail
PurposeRe-execute previously completed tasks in shadow mode to validate that the substrate produces consistent results and to identify regressions
Data SourceHistorical task execution records from agency_tasks
OutputComparison report between original and shadow execution results
Use CasePost-deployment validation, regression detection, consistency auditing

3.2 Synthetic

AttributeDetail
PurposeGenerate synthetic edge-case scenarios that test boundary conditions, unusual input patterns, and adversarial payloads against the substrate
Data SourceAI-generated synthetic inputs based on known vulnerability patterns and edge cases
OutputVulnerability report with confidence scores and remediation suggestions
Use CaseProactive hardening, zero-day preparation, fuzzing-style resilience testing

3.3 ENCODE Practice

AttributeDetail
PurposeTrain the ENCODE module's code generation and execution capabilities by running sandboxed code exercises against the substrate's execution environment
Data SourceCurriculum tiers from EncodedLearningCard — Core Patterns through Specialization
OutputCompetency scores, execution traces, and learned heuristics fed back into the ENCODE module
Use CaseENCODE skill development, sandbox validation, graduated autonomy progression

3.4 Run All

AttributeDetail
PurposeExecute all three training modes (Replay, Synthetic, ENCODE Practice) in sequence as a comprehensive training cycle
Execution OrderReplay Tasks → Synthetic → ENCODE Practice
OutputAggregated training report with per-mode summaries and overall substrate health delta
Use CaseComprehensive pre-deployment validation, scheduled deep training cycles

5. Confidence Gating

All training outputs pass through the substrate's confidence gating system before being promoted to production rules:

  • Below 0.6: Discarded — insufficient evidence
  • 0.6–0.8: Staged — requires additional validation cycles
  • Above 0.8: Promoted — automatically applied to the immunity mesh

6. Access Control

  • All training modes require admin or governor role
  • The Immunity Mesh Dashboard is gated by AdminRoute in App.tsx
  • Auto Training toggle persists via system_flags with RLS enforcement

7. Monitoring

Training activity is visible through multiple channels:

  • Controls Tab: Auto Training toggle state and last run indicator
  • Analytics Tab: Shadow Mesh Analytics with probe success rates
  • Repair Skills Tab: Learned rules inventory with confidence scores and adoption counts
  • Shadow Build Tab: Per-mode last run summary and status indicators
