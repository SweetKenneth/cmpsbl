1. 3-Lane Integrity Scoring

The substrate uses a 3-lane integrity model replacing the legacy single-scalar WMI:

Availability (0.35)

Uptime + breaker penalties + quarantine status

Correctness (0.40)

Error rate + validation failures + contradiction signals

Performance (0.25)

P95 + P99 latency + regression against baseline

// Source: src/lib/system/integrity/types.ts
DEFAULT_INTEGRITY_WEIGHTS = {
  availability: 0.35,
  correctness:  0.40,
  performance:  0.25,
}

// Default mode: weighted (prevents transient single-lane false degradation)
total = 0.40 × correctness + 0.35 × availability + 0.25 × performance

// Safe Mode escalation forces pessimistic:
total = min(availability, correctness, performance)

// Module weight constants:
MAX_MODULE_WEIGHT    = 0.25
BLAST_RADIUS_K       = 0.15
WEIGHT_SUM_TOLERANCE = 0.001

Weight Invariants

  • Weight sum must equal exactly 1.000 (tolerance: ±0.001) — build fails if violated
  • No single module weight may exceed 0.25
  • Integrity score < 40 triggers auto-heal consideration
  • Integrity score < 60 blocks evolution promotion
  • Weights are immutable during a release epoch

3. Clockless Execution Model

The system operates on a demand-pulled, event-driven execution model. No timers, no cron jobs, no fixed polling intervals.

Strategic Value: Reduces infrastructure cost while maintaining responsiveness. Prevents false-positive health degradation caused by timer-based polling during low-activity periods.

Key Properties

  • No idle compute cost — modules only activate when work exists
  • Deterministic health accounting — computed from actual events, not timer ticks
  • Triple-deferred boot — Defer 1: Registry population → Defer 2: Dependency graph validation → Defer 3: Health gate verification

4. SM-2 Spaced Repetition + RPS

Governs memory tiering and knowledge retention across the MEMORY module.

Core Variables

VariableDescriptionDefault
easeFactorMultiplier for interval growth2.5
intervalDays until next review1
repetitionsSuccessful recall count0
retentionRatePercentage of memories retained0.85 target

Algorithm

After each recall attempt with quality q (0-5):

if q >= 3 (successful recall):
  if repetitions == 0: interval = 1
  if repetitions == 1: interval = 6
  else: interval = interval × easeFactor
  repetitions += 1
else:
  repetitions = 0
  interval = 1

easeFactor = max(1.3, easeFactor + (0.1 - (5 - q) × (0.08 + (5 - q) × 0.02)))

Memory RPS (Recall Priority Score)

🔒 Trade Secret — Scoring Model

RPS combines recall frequency, contradiction penalties, credibility weighting, and recency to produce a single priority score for memory retrieval ordering. Contradiction penalties reduce score by 0.15 per flagged inconsistency. Credibility weighting uses source-tier multipliers (0.5–1.0).

8. Cascade Containment

3-tier cascade containment model with governor-controlled Safe Mode:

SeverityTriggerResponse
S1≥ 3 modules fail within 30sOpen breakers on affected downstream
S2Fan-out or cyclic cascadeIsolate origin, quarantine zone
S3Persistent S2 for > 2 minutesActivate Safe Mode (pessimistic integrity)

Cascade events are persisted to cascade_events table with severity, origin module, affected modules, and actions taken. Safe Mode state is durable in substrate_safe_mode.

9. Merkle Audit Chain

Tamper-evident, cryptographic logging of all evolution receipts and governance decisions.

Receipt[n].chainHash = SHA-256(Receipt[n-1].chainHash + Receipt[n].contentHash)
Receipt[0].previousHash = '0'.repeat(64)  // Genesis block

// Verification: recompute from genesis, compare each stored chainHash
// Any mismatch = tampering detected

Chain heads are anchored to audit_chain_anchors every 100 receipts across two redundant stores (primary + redundant) for tamper detection.

10. Cognitive Load Balancing

routeScore(provider, task) = 
  healthWeight    × provider.healthScore
  + costWeight    × (1 - provider.normalizedCost)
  + affinityWeight × provider.taskAffinity[task.type]
  + latencyWeight  × (1 - provider.normalizedLatency)

Routing Factors

  1. Task classification — semantic analysis determines category (chat, analysis, generation, code, classification)
  2. Context window matching — skip provider if input_tokens > max_context × 0.9
  3. Cost-aware scoring — factor in per-token cost against budget
  4. Health weighting — prefer providers with higher uptime
  5. Affinity scoring — learned per-task-type performance preferences (persisted in nexus_provider_affinity)
  6. Sticky routing — constraints-first with session affinity

17. SLO-Based Health Grading

GradeScore RangeMeaning
A90–100Optimal — no action needed
B75–89Healthy — minor items
C60–74Acceptable — monitor closely
D40–59Degraded — active investigation
F0–39Critical — auto-heal triggered

Composite Score Formula

score = 0.25 × uptime_24h
      + 0.25 × error_rate_1h (inverted)
      + 0.20 × circuit_state (closed=1.0, half=0.5, open=0.0)
      + 0.15 × p95_latency (normalized against baseline)
      + 0.15 × quarantine_state (1.0 if not quarantined)

SLO-based grading tracks uptime targets, error rate ceilings, P99 latency budgets, and MTTR per module.
