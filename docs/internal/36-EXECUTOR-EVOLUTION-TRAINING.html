Overview

The Executor EVOLUTION Training System extends the EVOLUTION Mesh with 16 capabilities organized across three domains: Training, Diagnostics, and Knowledge. These systems enable executors to develop structured competency, self-diagnose performance issues, and accumulate institutional knowledge — all within isolation boundaries.

1.2 Replay Sandbox

TRAINING training/replay-sandbox.ts

Captures failed execution gaps as snapshots. Executors can replay the same inputs to practice handling previously-failed scenarios. Tracks resolution rates and attempts-to-resolve.

Key functions: captureGap(), replayGap(), getUnresolvedGaps(), getReplayStats()

1.3 Warm-Up Sequences

TRAINING training/warmup.ts

Pre-mutation readiness checks run before high-stakes operations. Four phases: schema check, repair engine check, shadow dry run, and rollback readiness verification.

Required phases must pass before mutation is permitted. Optional phases (shadow dry run) are advisory.

2. Diagnostics Domain

2.1 Micro-Feedback Loops

DIAGNOSTICS diagnostics/micro-feedback.ts

Step-by-step reasoning analysis within a single mutation lifecycle. Captures granular decision signals (positive/negative/neutral) per phase. Auto-derives insights: bottleneck detection, cascade failure patterns, recovery detection.

2.2 Skill Decay Detection

DIAGNOSTICS diagnostics/skill-decay.ts

Monitors executor skill performance over 7-day sliding windows. Detects three alert types:

  • Performance decay — gradual success rate drop (≥15% from peak)
  • Inactivity decay — no activity for 14+ days
  • Sudden drop — ≥25% drop within a single window

2.3 Confidence Calibration Tracker

DIAGNOSTICS diagnostics/confidence-calibration.ts

Measures alignment between executor predicted confidence and actual outcomes using Expected Calibration Error (ECE). Grades: excellent (<5% ECE), good (<10%), fair (<20%), poor (≥20%). Detects overconfidence (positive bias) and underconfidence (negative bias).

2.4 EVOLUTION Stamina Metrics

DIAGNOSTICS diagnostics/stamina-metrics.ts

Tracks quality degradation over extended mutation sessions. Fatigue detection triggers when ≥2 of 3 signals appear: success rate drop ≥15%, latency increase ≥25%, repair rate increase ≥20%. Recommends cooldown periods proportional to session length (max 6 hours).

2.5 Mutation Complexity Scoring

DIAGNOSTICS diagnostics/mutation-complexity.ts

Scores proposed mutations across 6 weighted dimensions before execution:

Scope Breadth       (25%) — modules affected / 24
Change Volume       (15%) — lines changed / 500
Safety Sensitivity  (20%) — touches DEFENSE/routing/MEMORY
Test Coverage Gap   (15%) — 1 - regression coverage
Historical Risk     (10%) — prior failures on similar
Reversibility       (15%) — irreversible = 1.0

Grades: trivial → simple → moderate → complex → critical. Maps to recommended executor tier.

2.6 Failure Taxonomy Engine

DIAGNOSTICS diagnostics/failure-taxonomy.ts

Classifies all failures into 9 categories: input_quality, schema_mismatch, repair_exhaustion, timeout, cascade_failure, resource_limit, governance_block, regression_detected, unknown. Auto-generates root cause analysis and suggested actions. Detects repeat patterns within 24h windows.

2.7 Post-Mortem Auto-Generator

DIAGNOSTICS diagnostics/postmortem.ts

Auto-generates structured post-mortems (P0–P3) from failed evolution attempts. Includes timeline, root cause analysis, impact assessment, resolution actions, lessons learned, and prevention measures. Searchable by tag, category, and severity.

2.8 Repair Strategy Effectiveness Tracking

DIAGNOSTICS diagnostics/repair-effectiveness.ts

Measures which repair strategies work best for which archetypes. Provides ranked strategy lists, per-archetype breakdowns, and trend detection (improving/stable/declining). Informs strategy selection priority ordering.

3. Knowledge Domain

3.1 Pattern & Anti-Pattern Library

KNOWLEDGE knowledge/pattern-library.ts

Curated library of 8 seed entries (patterns and anti-patterns), RCA-indexed. Includes:

  • Patterns: Pre-flight validation, deterministic repair before escalation, shadow mode for high-risk, atomic rollback, warm-up before high-stakes
  • Anti-Patterns: Partial state rollback, repair without re-validation, stacking evolutions without cooldown

Library grows via addPattern(). Reference counts track usage.

3.2 Domain Specialty Trees

KNOWLEDGE knowledge/domain-specialty.ts

Tree-structured mastery tracking across 5 domains: Repair, Schema, Routing, DEFENSE, EVOLUTION. 23 nodes total with parent-child unlock mechanics. Children unlock when parent mastery exceeds threshold (60–80%).

3.3 Knowledge Packs

KNOWLEDGE knowledge/knowledge-packs.ts

Exportable bundles of curated patterns, repair strategies, and configuration recommendations. Status lifecycle: draft → reviewed → published → deprecated. Import filtering: low-confidence strategies (<0.6) and low-success patterns (<0.5) are auto-skipped. Self-import prevention enforced.

4. Deliberately Excluded

The following capabilities were evaluated and intentionally excluded from this build:

Cross-Executor Knowledge Transfer — Introduces contamination risk, blurs performance attribution, complicates debugging, makes failures harder to trace. Early evolution needs isolation.

Progressive Autonomy Unlocks — Permission systems before stability create chaos. Build when executor volume reaches 10x current levels.

Risk Intuition Training — Useful calibration tool but not core to the repair/build loop.

Synthetic Gap Generator — Synthetic environments often create false confidence. Use real gaps first via Replay Sandbox. Synthetic generation deferred to Phase 2.

5. Integration Points

All 16 capabilities are exported from the main evolution-mesh/index.ts barrel file. Integration with existing systems:

  • wrap() → records outcomes to stamina, skill decay, repair effectiveness, and failure taxonomy
  • deterministicRepair() → records strategy outcomes to repair effectiveness tracker
  • shadow() → warm-up verifies shadow connectivity; complexity scorer recommends shadow for high-risk
  • Learning rules → pattern library provides lookup by RCA category; knowledge packs export learned rules
  • Telemetry → micro-feedback sessions feed into stamina metrics and confidence calibration
