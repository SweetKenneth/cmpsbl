Memory Tiering Internals

Classification: Internal
Epoch: SPARTA (v11.1)
Zone: MEMORY (CCR Sector)

1. Overview

The MEMORY zone implements a three-tier storage architecture with SM-2 spaced repetition for automatic tier management. Knowledge moves between hot, warm, and cold tiers based on access patterns and recall quality.

3. SM-2 Integration

Each memory entry maintains SM-2 spaced repetition metadata:

interface MemoryEntry {
  key: string;           // Unique identifier (1–256 chars)
  content: unknown;      // Stored knowledge
  tier: 'hot' | 'warm' | 'cold';
  
  // SM-2 fields
  easeFactor: number;    // Starting at 2.5, min 1.3
  interval: number;      // Days until next review
  repetitions: number;   // Successful recall count
  nextReview: number;    // Unix timestamp
  
  // Tracking
  lastAccess: number;    // Unix timestamp
  accessCount: number;   // Total recalls
  quality: number;       // Last recall quality (0–5)
}

4. Tier Promotion & Demotion

4.1 Promotion (Cold → Warm → Hot)

Entries are promoted when:

  • Accessed within the tier's freshness threshold
  • SM-2 quality score ≥ 3 on last recall
  • Destination tier has capacity (or LRU eviction makes space)

4.2 Demotion (Hot → Warm → Cold)

Entries are demoted when:

  • Not accessed within the tier's freshness threshold
  • SM-2 next review date has passed without recall
  • Tier is at capacity and entry is LRU candidate

4.3 Permanent Eviction

Cold tier entries are permanently evicted when:

  • Cold tier at max capacity (10,000) and entry is LRU
  • SM-2 ease factor has dropped below 1.3 (learned poorly)
  • Entry has not been accessed in 90 days

6. Feedback Loop

Recall Request
  → Search across tiers (hot first, then warm, then cold)
  → Return result + record access
  → Caller reports recall quality (0–5)
  → SM-2 algorithm updates interval + ease factor
  → Tier promotion/demotion evaluated
  → Feedback log appended (bounded to 1,000 entries)
