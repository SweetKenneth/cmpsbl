## 1. Purpose

This document covers the internal architecture of the Discovery Engine — the recursive reactor at the heart of the Autonomous Software Foundry. This is the substrate's most commercially sensitive algorithm after the SEBA promotion pipeline.

## 2. Reactor Architecture

### 2.1 Core Loop

The discovery reactor operates as a bounded recursive search:

```
Input:  40-node topology graph
Output: Scored, tiered, deduplicated capability manifest

1. Generate candidate pool from module combinations (depth 2–5)
2. For each candidate:
   a. Compute semantic signature (embedding hash)
   b. Check deduplication index (cosine > 0.92 = skip)
   c. Score via CJPI (4-factor weighted composite)
   d. Auto-tier based on score thresholds
   e. Persist to discovery table
3. Rank within each tier
4. Emit discovery event to RIPPLE
```

### 2.2 Candidate Generation

Candidates are generated by walking the dependency graph:

- **Depth 2:** All pairwise module combinations (38 × 37 = 1,406 pairs)
- **Depth 3:** Filtered triples (high-affinity pairs extended by one hop)
- **Depth 4–5:** Only extends from top-scoring depth-3 chains

This pruning strategy keeps the search space manageable (~50,000 evaluable candidates) while ensuring coverage of the full topology.

### 2.3 Semantic Deduplication

Each candidate receives a semantic signature:

```
signature = embed(name + description + module_chain.join('→'))
```

Before persisting, the signature is compared against all existing discoveries:
- Cosine similarity > 0.92 → duplicate, skip
- Cosine similarity 0.80–0.92 → variant, persist with `variant_of` reference
- Cosine similarity < 0.80 → novel, persist as new

### 2.4 CJPI Scoring Detail

The Crown Jewel Pipeline Index computation:

```
novelty     = 1 - max(cosine_similarity(candidate, existing_set))
utility     = heuristic_utility_score(description, module_chain)
complexity  = chain_depth * dependency_diversity * integration_score
composability = count(compatible_chain_extensions) / max_possible_extensions

CJPI = (0.25 * novelty + 0.30 * utility + 0.20 * complexity + 0.25 * composability) * 100
```

**Utility heuristic factors:**
- Presence of NEXUS (routing) → +0.15
- Presence of BRAIN/MEMORY (cognitive) → +0.10
- Presence of DEFENSE (security) → +0.10
- Cross-zone chains (e.g., ESZ→EMZ) → +0.20

## 3. Module Self-Discovery

Beyond the reactor's combinatorial search, each module runs its own discovery process:

### 3.1 Process (`src/lib/substrate/intent-mesh/module-discovery.ts`)

1. Module enumerates all registered actions
2. Runs each action with synthetic inputs
3. Observes emergent behaviors (unexpected output patterns)
4. Reports emergent capabilities to the reactor for scoring
5. CJPI scoring is applied to self-discovered capabilities identically

### 3.2 Emergent Capability Detection

An "emergent capability" is defined as an action that:
- Produces output significantly different from its documented behavior
- Chains with another module's action to produce a novel combined effect
- Demonstrates learning (output quality improves with repeated invocation)

## 4. Standalone Packaging

### 4.1 Standalone Runtime (`src/lib/export/standalone-runtime.ts`)

A micro-substrate that provides:
- CJPI scoring function
- Auto-tiering function
- Pipeline orchestration (sequential chain execution)
- No external dependencies — runs in any TypeScript environment

### 4.2 Standalone Discovery Engine (`src/lib/export/standalone-discovery-engine.ts`)

Portable version of the reactor:
- Uses the standalone runtime for scoring
- Can ingest an existing discovery manifest and re-score/re-tier
- Can run limited discovery on a provided topology graph
- Included in every S-Tier Vault ZIP export

| Metric | Value |
