3. Shadow Probe Implementation

The customer-facing shadow probe system uses a simplified version of the substrate's A/B testing infrastructure:

Customer Shadow Probe Pipeline:
  1. Accept JSON input from dashboard
  2. Execute baseline function with timing
  3. Execute candidate function with timing
  4. Compare outputs (deep equality check)
  5. Return timing delta + match/diverge result

Internal Shadow Pipeline (what we DON'T expose):
  1–5. Same as above
  6. Feed divergence patterns to DREAM state
  7. Update salience scores in BRAIN
  8. Generate evolution proposals via MODERNIZER
  9. Apply governance bounds via CORTEX
  10. Store immutable audit record via SCRIBE

4. Learning Test Internals

Learning tests expose a subset of VOLVER's skill analysis. Internally, they work differently:

Customer Learning Test:
  Input:  Task description (string)
  Match:  Filter VOLVER_SKILLS by category
  Output: Matching skills, average proficiency, suggestion string

Internal Learning Analysis (ENCODE):
  Input:  Task description + full substrate context
  Match:  All 20 modules contribute context
  Analysis: Cross-reference with DREAM heuristics
  Output: Full diff proposal with confidence scoring,
          regression risk assessment, and rollback plan
