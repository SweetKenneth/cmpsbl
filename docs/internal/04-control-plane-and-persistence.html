3. Atomic Versioning

All 10 domains are committed in a single transactional revision with tamper-evidence:

snapshotHash = SHA-256(canonicalizeJson({
  flags, config, canaries, retryBudgets, metrics,
  cascadeHistory, idempotencyStore, schemas, queueState, chaosRules
}))

5. Write-Ahead Log (WAL)

interface WalEvent {
  id: string;
  domain: string;      // Which of the 10 domains
  operation: string;    // 'set' | 'delete' | 'merge'
  key: string;
  value: unknown;
  timestamp: number;
  instanceId: string;
}
  • Events buffered in memory, flushed every 30s (leader only)
  • Buffer limit: 1000 events — force flush on overflow
  • drainWalEvents() flushes immediately

6. Rehydration

1. Query cp_revisions ORDER BY committed_at DESC LIMIT 1
2. Load all 10 domain tables for that revision_id
3. Verify snapshot hash matches stored hash
4. If valid: populate in-memory state
5. If invalid: log integrity violation, attempt previous revision
6. Replay any WAL events after the revision's committed_at

8. Degraded Mode

⚠ Degraded State

If persistence fails (database unreachable): system continues from in-memory state, WAL events accumulate in memory buffer, no snapshots committed. On recovery: flush accumulated WAL, commit snapshot, exit degraded mode.
