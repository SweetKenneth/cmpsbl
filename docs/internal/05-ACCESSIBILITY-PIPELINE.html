♿ Accessibility Pipeline (Inclusive Module)

How We Enforce WCAG Compliance

The 4-Stage A11y Pipeline

CRAWL → SCAN → ANALYZE → REPAIR │ │ │ │ │ │ │ └─ Generate fix suggestions │ │ └─ WCAG 2.2 compliance check │ └─ DOM/ARIA inspection └─ Page discovery & rendering

Template Blocking

Before any template is published:

  1. The Inclusive module scans the rendered output
  2. Critical violations (Level A failures) trigger BLOCK status
  3. Template cannot be published until resolved
  4. Each issue includes an automated repair suggestion
🔐 The Scoring Secret: The scanner uses a weighted scoring system: 
score = 100 - (critical × 20) - (serious × 10) - (moderate × 5) - (minor × 1)
Templates must achieve minimum score (typically 80+) to pass. This is why "perfect" accessibility is enforced—it's mathematically gated.

Repair Suggestions

Each violation generates a concrete fix:

{
  issue: "Image missing alt attribute",
  element: "<img src='hero.jpg'>",
  wcag: "1.1.1 Non-text Content (Level A)",
  fix: "<img src='hero.jpg' alt='Descriptive text here'>"
}
