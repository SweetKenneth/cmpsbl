1. Circuit Breaker System

CLOSED→ failures ≥ 3 → OPEN→ 60s → HALF-OPEN→ 2 successes → CLOSED

State is DB-persisted (circuit_breaker_state). Failure counting uses sliding-window queries against circuit_breaker_failures. Exponential backoff with jitter governs retry. Each module has its own independent breaker instance.

2. Dead Letter Queue

CommandAction
ripple.dlqList all DLQ items

3. Retry Budgets (Token Bucket)

10 tokens per 60-second period per module. When tokens = 0, retries blocked until refill.

4. Saga Orchestration

Step 1: Execute → Success → Continue
Step 2: Execute → Success → Continue
Step 3: Execute → FAIL
  → Compensate Step 2
  → Compensate Step 1
  → Report failure

7. Self-Healing Recovery

1. Detect degraded health
2. Identify recovery strategy
3. Execute recovery (circuit reset, state flush, restart)
4. Wait for health re-check
5. If improved: log, resume
6. If not: escalate to governor
