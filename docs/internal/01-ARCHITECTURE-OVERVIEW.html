📐 Architecture Overview

The 14-Module Cognitive Orchestration System

What Is Substrate OS?

Substrate OS is not a traditional application. It's a cognitive orchestration layer for AI systems that can:

  • Self-Evolve: Automatically propose and apply improvements to itself
  • Self-Heal: Detect failures and recover without human intervention
  • Remember: Maintain structured memory with tiered retention
  • Reason: Apply multiple cognitive engines to solve problems

Think of it as an operating system for AI agents—providing scheduling, memory, security, routing, and observability.

How Modules Communicate

The RIPPLE Event Bus

Modules communicate through the RIPPLE event bus, not direct function calls. This provides:

  • Loose Coupling: Modules don't know about each other's internals
  • Audit Trail: Every inter-module message is logged
  • Async Processing: Non-blocking communication
  • Replay Capability: Events can be replayed for debugging
// Publishing an event
ripple.emit('brain.memory.stored', { memory_id: '...', type: 'fact' });

// Subscribing to events
ripple.on('brain.memory.*', async (event) => {
  // React to any brain memory event
});

Request Flow Example

User Request → DECODE (parse intent) ↓ CORTEX (validate policy) ↓ NEXUS (route to AI provider) ↓ BRAIN (store result) ↓ RIPPLE (emit completion event) ↓ Response to User

Module Independence & Health

🔐 The Secret: Each module maintains its own health score (0-100) and circuit breaker state. If BRAIN fails 3 times, only BRAIN is blocked—all other modules continue operating. This isolation architecture is why partial failures never cascade into full system outages.

Health Score Calculation

// Each module tracks:
{
  health_score: 100,        // 0-100, auto-calculated
  status: 'healthy',        // healthy | degraded | critical
  circuit_state: 'closed',  // closed | open | half-open
  consecutive_failures: 0,
  consecutive_successes: 0,
  last_success: timestamp,
  last_failure: null
}

The Cortex Orchestrator

CORTEX sits above all other modules as the "brain stem" of the system. It:

  • Enforces governance policies across all modules
  • Coordinates multi-module operations (like evolution)
  • Runs background cycles (mutation, reflection, synthesis)
  • Manages system-wide state and configuration

Cortex Phases

CORTEX cycles through 4 phases continuously:

  1. Observation: Gather system state from all modules
  2. Mutation: Apply pending changes
  3. Reflection: Analyze outcomes and store learnings
  4. Synthesis: Generate improvement proposals
