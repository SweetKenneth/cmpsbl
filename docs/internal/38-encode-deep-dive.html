1. Identity & Archetype

ENCODE is the substrate's code execution engine — Node #21 in the 40-node / 12-sector matrix. It is a first-class substrate module responsible for receiving structured task packets from DECODE and producing governed, audited code artifacts.

Archetype: The Precision Forge

  • Never generates code without architecture context — requires an audit snapshot before any execution
  • Never executes without human approval — execution lock protocol enforces bidirectional consent
  • Fail-closed by default — any invariant violation blocks execution
  • Routes through NEXUS fleet — zero external AI costs (Groq → Cerebras → DeepSeek)
  • Learns from every execution — CLM integration with brain writeback

These roles are compile-time constants. They cannot be overridden at runtime. DECODE can never generate code. ENCODE can never redefine architecture. The USER is always the strategic authority.

2. ENCODE + DECODE Pipeline Architecture

The DECODE → ENCODE pipeline is a 7-stage execution chain with mandatory approval gates.

INPUT→ ANALYZE→ CLASSIFY→ PLAN→ APPROVAL→ EXECUTE→ OUTPUT

Stage 1–2: Intent → DECODE Parsing

User's natural language enters via submitIntentForReview(). DECODE parses the intent — it cannot generate code, only translate and classify.

Stage 3: Plan Generation

planFromIntent() generates a structured PatchPlan with plan_id, title, affected modules, risks, and status. Published to the module bus for GOVERNANCE veto.

Stage 4: Approval Gate (Critical)

planFromIntent() → PatchPlan (status: 'draft')
approvePlan()    → PatchPlan (status: 'approved')
routeFromDecode() → ONLY works if plan.status === 'approved'
🔒 Trade Secret
If you call routeFromDecode() without a plan_id, it throws. If the plan is not approved, it throws. There is no bypass. The plan is also structurally verified via verifyPlan().

Stage 5: Brain Recall → Task Enqueue

Before execution, ENCODE recalls context from BRAIN via recallForEncode(). The task is enqueued as a structured EncodeTaskPacket with validated intent (max 5000 chars), target surface, constraints, brain keys, and acceptance criteria.

Stage 6–7: Completion & Writeback

completeAndWriteback() records results, seals artifacts into a hash chain, and writes learnings back to BRAIN. Failed tasks auto-record to the error-pattern library.

13. CLM — Internal Codebase Learning Mode

ENCODE's CLM is internal-focused — studies 32 module directories, 42 critical files, 11 pattern matchers. Each cycle produces learnings, upgrades, risks, and insights. Feeds Knowledge Distillery to push learnings to executor swarm.

🔒 Trade Secret
CLM doesn't read files — it analyzes known directory structures, pattern matchers, and task history. Metadata-driven, not content-driven. Real codebase knowledge comes from the knowledge transfer pipeline.

15. Customer-Facing Stub (VOLVER)

VOLVER is ENCODE's deliberately limited customer-facing version: 8 skills (vs 31), proficiency capped 20-30 points lower, always dry-run, never writes code.

⚠ Product Moat
The proficiency gap is the upgrade driver. Customers see capability but only get partial execution. The "dry-run only" constraint ensures VOLVER never accidentally writes code.

16. Secrets & Trade-Secret Mechanisms

Architectural Secrets

  • Dual-condition execution lock (architecture + approval) — no programmatic bypass
  • FNV-1a hash chain creates tamper-evident generation history
  • 25-point hardening not available in any competing code agent
  • 7-strategy escalation cascade with quality scoring
  • Bidirectional Brain loop — ENCODE both consumes and produces memories

Algorithmic Secrets

  • Health: successRate × 60 + queueHealth(20 - pending × 2) + recencyBonus
  • Priority: severity(0-40) + escalation(15) + core(10) + userRequested(20) + aging(5)
  • Resolution quality: deterministic(1.0) > learning_rule(0.9) > pattern(0.6) > auto_expire(0.1)

Security Secrets

  • 30+ narrative blockers prevent AI personality in generated code
  • Import allowlist — only approved packages
  • Path traversal prevention — rejects .., //, leading /
  • Service key detection — flags any service_role references
