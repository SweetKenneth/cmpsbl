# How It Works

---

## The Architecture (Simplified)

CMPSBL is built from **40 specialized primitives** organized into four categories:

```
🛡️ LAYERS (Security & Governance — protect everything)
  🫀 ORGANS (Core Infrastructure — boot, reason, remember)
    ⚙️ ENGINES (Processing — routing, synthesis, orchestration)
      🤖 AGENTS (Autonomous Actors — code, language, vision)
```

### What Each Category Does

| Category | Primitives | Purpose |
|----------|-----------|---------|
| **Organs** | CORE, SYSTEM, BRAIN, MEMORY, NERVE, RELAY, RIPPLE, ACCESS, IDENTITY, AUDIT | The kernel — boots, reasons, remembers, enforces rules |
| **Layers** | DEFENSE, IMMUNITY, GOVERNANCE, INTENT, EVOLUTION, SHADOW, PHANTOM | Always-on protection, governance, and self-improvement |
| **Engines** | DREAM, CORTEX, NEXUS, ORACLE, FORGE, ECHO, ECONOMY, ENGINEER, ATLAS, CLM | On-demand processing for complex tasks |
| **Agents** | DECODE, ENCODE, VISION, HARVEST, LINGUA, COMPASS, CONSCIENCE, TREATY, SOVEREIGN, MEDIC, INCLUSIVE, INTEGRATION, REFLEX, SANDBOX, OBSERVER | Specialized AI workers for specific domains |

## How Requests Flow

1. Your request arrives at **DEFENSE Layer** — threat assessment
2. **NEXUS Engine** routes it to the best AI provider and model
3. The right **Agent** processes it (DECODE Agent for language, ENCODE Agent for code, etc.)
4. **BRAIN Organ** and **MEMORY Organ** provide reasoning and context
5. **AUDIT Organ** logs everything
6. Response returns through **DEFENSE Layer** back to you

Every step is governed, audited, and observable.

---

## Health & Reliability

Each of the 40 primitives has its own **circuit breaker**. If one primitive has problems:

- It isolates automatically
- The rest of the system continues working
- **MEDIC Agent** attempts auto-healing
- You're notified if manual intervention is needed

System health is a **deterministic score** — a weighted sum of all 40 primitives, not a guess.

## Memory & Learning

CMPSBL remembers across sessions through a 4-tier memory system:

| Tier | Speed | What's Stored |
|------|-------|--------------|
| **Hot** | Instant | Active session context |
| **Warm** | Fast | Recent tasks and learning |
| **Cold** | Standard | Historical data and completed work |
| **Glacier** | Archive | Long-term retention |

Knowledge moves between tiers automatically based on usage patterns. The system also runs **Constant Learning Mode (CLM)** — continuously processing topics and compounding knowledge.

---

## Evolution

The system improves itself through a validated pipeline:

1. Changes are proposed (by the system or operators)
2. **SHADOW Layer** runs tests against real inputs in isolation
3. **7 validation gates** must pass (including truth preservation)
4. Only then does the change reach production
5. If anything goes wrong, **automatic rollback** activates

No untested change ever reaches production.

---

## Memory Chains

Memory chains are automated multi-primitive workflows that fire when specific conditions are met. They represent the substrate's coordination and immune-response system — enabling primitives to work as a unit rather than in isolation. The substrate has **100 primary memory chains** across 9 categories, from threat response to cognitive fusion.
