## What Is Ascension?

Ascension is CMPSBL's **software curing engine**. Upload any working code — in any language — and the substrate's **159-primitive matrix** across 12 vertical substrates tests, analyzes, and augments it into enhanced capabilities. The original code is preserved and runs first. CMPSBL wraps around it, adding intelligence, observability, and portability without changing a single line of the original logic.

**This is not AI.** Ascension uses pure algorithmic pattern detection — deterministic primitive-chain synthesis, lexical + structural analysis, and formula-based scoring. No neural networks. No language models. Same input → same output, always.

## How It Works

### 1. Upload

Upload a source file (any of 90+ supported languages). The Ascension Engine accepts it as a first-class participant in the substrate's discovery process.

### 2. Discovery

The 159-primitive matrix scans the uploaded code. Each primitive asks: "Does this code's behavior combine meaningfully with my capabilities?" Successful combinations are scored and recorded via the **CJPI scoring formula**.

### 3. Curing

Discoveries that match real architectural patterns become **capabilities** — the substrate identifies structural weaknesses, generates the specific capability to address them, and attaches them via the **Mana** Layer 2 engine without modifying the original source.

### 4. Export

Export as a ZIP archive containing:

1. **Original source code** — untouched (Layer 1), verified via SHA-256
2. **Convex Core™ Processing Layer** — standalone execution environment (DPL)
3. **Mana attachment manifest** — the Layer 2 capability bindings
4. **14+ branded HTML documents** — auto-generated technical guides
5. **Verification suite** — CJPI certificate, capability ledger, runtime proof
6. **Lifecycle artifacts** — changelogs, license FAQs, migration guides

If CMPSBL disappeared tomorrow, the export still runs. That's the portability guarantee.

### 5. Verify

Side-by-side code confirmation and integrity verification. Every function call is evaluated against a behavioral contract and enforced when violated. The **Runtime Proof** report confirms deterministic behavioral evidence.

### 6. Runtime Integration (Optional)

For runtime governance, use the production API:

```typescript
import { init } from '@cmpsbl/runtime';
const session = init(myLib, sourceCode, { name: 'my-lib' });

// Drop-in replacement — same signatures, now governed

// Quick-glance status for dashboards
```

No framework changes. No rewrites. No lock-in. The original module is never modified — all behavior is attached at runtime.

## Discovery Scoring (CJPI)

Every discovery receives a **Crown Jewel Pipeline Index** score based on six factors:

| Factor | Weight | What It Measures |
|--------|--------|-----------------|
| Signal Affinity | 35% | How many primitive detection patterns match |
| Raw Density | 10% | Structural complexity of the chain |
| Capability Match | 15% | Alignment with 25 behavioral archetypes |
| Ascension/Wow | 15% | Novelty and emergence potential |
| Structural Archetype | 12% | Fit within scanner archetype library |
| Vertical Affinity | 10% | Domain-specific relevance across 12 verticals |

**This is a deterministic formula.** No neural network. No probabilistic inference. Given the same inputs, it produces the same score — every time.

High-scoring discoveries are automatically promoted. The highest-tier discoveries (CJPI ≥ 95) are classified as **S-Tier Crown Jewels** and federated across all 12 vertical registries.
