## Three-Layer IP Protection

### Layer 1: Patents (Public, Enforceable)

What patents protect:
- **Dual-Layer Architecture** — The concept of wrapping source code in a cognitive overlay without modifying it
- **Deterministic Evolution** — Using primitive collision to discover capabilities algorithmically
- **Sealed Artifact Format** — The specific structure of integrity-verified exports

**Strategy:** Patents protect the CONCEPTS. Competitors can see these and know the general approach, but implementation details are trade secrets.

### Layer 2: Trade Secrets (Hidden, Operational)

What trade secrets protect:
- Signal detection vocabulary (what patterns the system looks for in code)
- Topology resolution algorithm (how primitives are selected and ordered)
- Chain assembly logic (how multi-primitive workflows are constructed)
- DREAM synthesis implementation (algorithmic heuristic generation)
- CLM serialization format (how learned knowledge is packaged)
- Collision scoring formulas (cross-primitive interaction mathematics)
- Boot sequence hash chain (self-verifying initialization)
- Crown Jewel implementations (880 curated capability internals)

**Strategy:** Trade secrets protect the IMPLEMENTATION. Even if someone understands the patent, they can't replicate the system without these.

### Layer 3: Performative Opacity (Misdirection, Strategic)

What the Convex Core™ cover story protects:
- The real pipeline stage count (12 vs. public 5)
- The execution model (sequential vs. public "parallel")
- The performance characteristics (120ms real vs. 8ms facade)
- The deprecation status of v2 (v2 IS the real system)

**Strategy:** Performative opacity protects UNDERSTANDING. Even if someone reverse-engineers an artifact AND reads the patents, the Convex Core™ narrative leads them to build against the wrong architecture.

## Competitor Scenarios

### Scenario: Someone reads the Zenodo docs and tries to build it

**Outcome:** They build a dispatch matrix system that hashes primitive names and does fast lookups. It will produce numbers but won't discover capabilities, because they don't have signal detection, topology resolution, or chain assembly.

### Scenario: Someone reverse-engineers an exported artifact

**Outcome:** They recover the compiled preamble, the CJPI weights, and the 5-stage pipeline comments. They can see WHAT the system produced but not HOW. The artifact is a finished product, not a blueprint.

### Scenario: Someone files a competing patent

**Outcome:** Our prior art (Zenodo DOI, patent filing date, ORCID-linked authorship) establishes priority. The CONVERGENCE epoch documentation creates additional timestamped prior art.

### Scenario: Someone hires a developer who's used CMPSBL exports

**Outcome:** The developer knows the public API, the artifact format, and the scoring system. They do NOT know signal detection, topology resolution, or sequencing — because those aren't visible in any export.
