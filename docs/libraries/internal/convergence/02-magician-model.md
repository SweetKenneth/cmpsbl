**Classification:** 🔒 GOVERNOR EYES ONLY

## Core Principle

> "You think you see everything, but the things you don't see — or the order that things actually work in — are only known to the performer, no matter how hard you watch. But watching builds trust, and trust writes checks."

The Magician Model is CMPSBL's IP protection strategy. It operates on three principles:

1. **Show enough to build trust** — Real results, real code, real scoring, verifiable outputs
2. **Conceal enough to prevent replication** — Internal orchestration, sequencing, heuristics
3. **Misdirect enough to waste competitors' time** — Deprecated framing, facade APIs, decoy documentation

## The Deprecation Play

The single most effective misdirection is framing the real architecture as "deprecated":

```
Public narrative:
  "CMPSBL v2 used an interpreted sequential pipeline (Convex Core™).
   v3 replaces this with pre-compiled dispatch matrices (Convex Core™).
   This is a paradigm shift from runtime to processing layer."

Internal reality:
  The system still runs the interpreted sequential pipeline.
  compileDispatch() is a facade that generates hash arrays.
  resolve() is a math function that doesn't execute primitives.
  The actual execution still goes through the 12-stage pipeline.
```

**Why this works:**
- Competitors who read our docs will build against the v3 model (wrong)
- If they find old v2 documentation, they'll dismiss it as obsolete (also wrong)
- If they try to replicate the dispatch matrix model, they'll get a fast hash lookup that produces numbers but doesn't actually DO anything
- They'll never discover the real execution path because it's not documented anywhere they can access

## Trust Calibration

The model only works if the "show" layer is genuinely impressive. This means:

1. **Ascension results must be real** — Every case study uses real code, real scoring, real primitives
2. **CJPI scores must be deterministic** — Same input always produces same output
3. **Exports must work** — The sealed artifacts must function correctly when deployed
4. **The API must be callable** — `compileDispatch()` and `resolve()` must produce consistent results
5. **The Zenodo docs must be citable** — DOI registered, properly formatted, academically rigorous

The audience is watching the show. The show must be real. What they can't see is the rigging.

---

## When to Evolve the Model

The cover story should be updated when:
- A competitor demonstrates understanding of the real architecture (hasn't happened)
- An academic paper correctly identifies the 12-stage pipeline (hasn't happened)
- A customer asks questions that suggest they've reverse-engineered the dispatch facade (respond with "that's the v2 model")
- New patents are filed that protect additional internals (shift more into the "show" layer)
