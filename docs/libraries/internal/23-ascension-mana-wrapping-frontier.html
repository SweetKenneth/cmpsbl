1. Where Ascension + Mana stand today

Ascension (U.S. App. No. 64/029,678) discovers the shape of code — function boundaries, contracts, side effects, capability surface — and produces a deterministic manifest + fingerprint.

Mana (U.S. App. No. 64/031,637) is the Layer 2 runtime. It wraps host functions at their boundaries (no source modification required) and routes every call through Lex — the conscience layer that allows, denies, or transforms based on rules.

Convergence: Ascension's manifest feeds Mana's loader. The result is governed execution of code Mana didn't write.

Live in production today

  • live Function-boundary attachment (pre / around / post)
  • live Capability contracts + Lex priority-ordered rule evaluation
  • live Safe detach with in-flight call tracking
  • live Deterministic proof + telemetry per invocation
  • live Multi-package composition via manifest consumer
  • live Session-scoped engines (no cross-module state poisoning)

2. The wrapping spectrum — what "wrap" actually means

Wrapping is a ladder. Each rung gives more control and costs more access.

RungWhat we observe / controlAccess required
0. Black-box networkI/O at the HTTP boundaryJust a URL
1. Surface fingerprintStack, framework, auth flowPublic web
2. SDK / API wrapEvery call through vendor SDKPackage installed in our perimeter
3. Function-boundary (Mana today)Every call, args, return, timingSource or installed package
4. Module-graph wrapImports, side effects, dynamic loadsBuild-time or loader hook
5. Process wrapSyscalls, file I/O, network, envOS-level agent / sidecar
6. Kernel / hypervisorMemory, scheduling, hardwareKernel module / VM host
7. HardwareBus traffic, DMA, firmwarePhysical / firmware control
Today: Mana lives at rung 3 with reach into rung 4. Rungs 5–7 share the same architecture; only the injection point changes.

3. Discovering wrap points from the outside

Realistic surface-discovery tactics, ordered from passive to noisy:

Fully passive — no permission needed

  • HTTP headers (Server, X-Powered-By, CSP, cookies)
  • HTML fingerprints (script paths, CSS conventions, favicon hash)
  • JS bundle inspection (webpack chunks, source maps, library globals)
  • Network waterfall (CDN patterns, third-party SDKs, telemetry endpoints)
  • DNS, TLS cert SANs, ASN ownership
  • robots.txt, sitemap.xml, .well-known/

Active but standard (rate-limited, polite)

  • OpenAPI / GraphQL introspection probes
  • Auth flow walking (OAuth discovery, SAML metadata)
  • Error-message fingerprinting (forced 404/500 leaks frameworks)
  • WebSocket handshake inspection
  • Service worker + PWA manifest enumeration

Active and noisy — only with consent

  • Endpoint fuzzing
  • Auth boundary probing
  • Header injection / parameter pollution
Honest limit: without code or runtime access, we describe the target — we don't govern it. Discovery without injection is reconnaissance, not control.

5. Access points required, ranked by cost

To go from "we describe it" to "we govern it" you need one of these per target:

  1. Package install — easiest. npm install @cmpsbl/mana or equivalent.
  2. Build-step injection — webpack / vite / esbuild plugin, Babel / SWC transform.
  3. Runtime loader hook — Node --require, Python sitecustomize, Java -javaagent.
  4. Sidecar process — proxy in front of network or IPC.
  5. OS agent — eBPF (Linux), ETW (Windows), EndpointSecurity (macOS).
  6. Kernel / hypervisor — full system observability, full liability.
  7. Hardware tap — bus analyzer, firmware shim, custom silicon.
Each rung up is roughly 10× the engineering cost and 10× the trust the deployer must extend.

6. Capability ladder — most to least powerful (today)

Ranked by leverage per rule installed.

  1. Outcome arbitration — Lex can substitute return values, redact, transform, replay. Highest-leverage primitive in the system.
  2. Capability quarantine — suspend an entire capability class (e.g. network.egress.*) with one rule.
  3. Cross-call correlation — enforce invariants across a chain (auth → fetch → write).
  4. Deterministic replay — every call has a proof; sessions replay identically for audit or training.
  5. Adaptive policy — Lex rules driven by telemetry; auto-tighten on anomaly score.
  6. Shadow execution — run host call + candidate alternative, compare, promote winner (TSAC pattern).
  7. Capability composition — stack contracts; functions inherit the union.
  8. Time-boxed grants — TTL rules; auto-revoke without human cleanup.
  9. Per-tenant policy — same wrapped function, different rules per caller identity.
  10. Telemetry-only mode — no enforcement, just observation. The entry drug for skeptical adopters.
  11. Lex extended predicates — custom JS predicates per rule (already shipped).
  12. Safe detach with quiescence — remove governance without dropping in-flight work.
  13. Manifest-driven auto-deploy — Ascension produces rules; Mana applies them.
  14. Proof export — cryptographic receipt the host was governed. Sellable as a compliance artifact alone.
  15. Trace-time explainability — every deny cites its rule. No black-box refusals.

8. Markets this can credibly reach

  • Today, with current code: SaaS vendors wanting governed SDKs, regulated fintech wrapping internal services, AI agent platforms wanting deterministic tool-call governance.
  • With JVM + .NET agents: enterprise IT — every Fortune 500 has a wrap-our-vendors problem.
  • With kernel/eBPF + attestation: defense primes, intelligence labs, sovereign cloud, critical infrastructure. This is the "could you sell to the military" path. Realistic — requires FedRAMP, FIPS, supply-chain attestation, cleared partner.
  • With hardware root-of-trust: weapon systems, satellite, anything where "did the right code run?" is a life-safety question.
The substrate's structure — deterministic, proof-emitting, governance-first — maps almost exactly to NIST 800-53, CMMC L3+, IL5. The gap is paperwork and lab time, not architecture.

10. Is it dangerous?

Yes, if mis-aimed. Honest assessment:

  • The same primitive that lets us enforce a deny rule lets someone substitute a return value. In the wrong hands that's a supply-chain attack tool.
  • Proof emission is a defense — every action is attributable. But the rules themselves are powerful: whoever writes Lex rules controls behavior.
  • Mitigations already in the architecture: signed manifests, Governor-only rule registry, proof chain, registry bridge with explicit enforcement.
  • The danger isn't theoretical — it's the same danger eBPF, JVMTI, and Frida pose. We're in good company; we need the same operational discipline.
Rule of thumb: don't ship kernel/hypervisor capabilities until the rule-authoring chain is hardware-attested and multi-party-signed. The architecture supports it today; we just haven't lit it up.

11. The path to peak

If you decided to push this to its ceiling, the order is:

  1. Lock the rule supply chain — signed Lex bundles, multi-party approval for high-impact capabilities.
  2. Ship JVM + Python + .NET agents — most ROI per engineer-month.
  3. Add eBPF + ETW probes — same Lex, kernel reach.
  4. Wire TPM / secure-enclave attestation — required for high-trust markets.
  5. Build the federated rule exchange — regulators publish rules; regulated parties subscribe.
  6. Pursue FedRAMP Moderate, then FIPS 140-3 — paperwork, ~12–18 months, opens the doors.
  7. Co-develop with one defense lab — bespoke wrap targets validate the rest.
Realistic ceiling: a sovereign-grade, attested governance substrate for any code, anywhere, with cryptographic proof of behavior. A category-defining product.

12. Out of scope (intentionally)

  • Wrapping software without consent of the deployer.
  • Hidden / undetectable governance — every Mana attachment is observable; we keep it that way.
  • AI inside Lex rule evaluation — Lex stays deterministic. AI can propose rules; it does not decide outcomes at runtime.

Bottom line

Today we govern function boundaries with deterministic proof. The architecture is straight-line extendable to syscall, kernel, and hardware reach. The ceiling is genuinely defense- and lab-grade if we want to climb. The danger is real and already mitigated structurally; the remaining work is operational discipline and certification paperwork.
