# Signal Forge Loadouts

---

## What Are Loadouts?

Loadouts are **pre-built, working projects** generated by the Signal Forge engine. They are not templates. They are not starter kits. They are fully configured systems with identity, memory, defense, governance, and health signals already wired.

One command. Zero setup.

```bash
cmpsbl loadout build threat-detector
```

That's it. The project directory is created, primitives are bound, and the substrate is live. You write logic. The infrastructure is already running.

## CLI Commands

```bash
# List all available loadouts
cmpsbl loadout

# Same thing
cmpsbl loadout list

# Deploy a specific loadout
cmpsbl loadout build <loadout-id>

# Example
cmpsbl loadout build research-agent
```

## What's Included in Every Loadout

Every deployed loadout comes with:

1. **`index.ts`** — Entry point with primitives pre-bound. Customize this.
2. **`README.md`** — What's wired, what each primitive does, how to run.

And behind the scenes:

- **Identity** — Your API key and agent name carry over from `~/.cmpsbl/`
- **Memory** — Persistent across sessions, compounding with every run
- **DEFENSE** — Circuit breakers and threat scoring active from first execution
- **BEACON** — Health signals broadcasting immediately
- **GOVERNANCE** — Policy checks enforced at every operation
- **FAILSAFE** — Graceful degradation if any primitive goes down

## Why "Loadout" and Not "Template"

Templates are starting points that require hours of configuration. Loadouts are **deployed systems**. The distinction matters:

| Templates (Everywhere Else) | Loadouts (CMPSBL) |
|----------------------------|-------------------|
| Boilerplate you configure | Working system you customize |
| No memory | Persistent memory from first run |
| No monitoring | BEACON health signals active |
| No governance | GOVERNANCE policy checks enforced |
| No self-healing | FAILSAFE circuit breakers wired |
| Setup takes hours | Setup takes one command |

## Building Faster Here

The substrate handles infrastructure. Every loadout inherits:

- **Persistent Memory** — Knowledge compounds across sessions
- **Governed Execution** — Every action is checked and auditable  
- **Self-Healing** — Failures are detected and routed around
- **Continuous Learning** — CLM cycles improve the system daily
- **Defense-in-Depth** — Threat scoring runs on every input

You don't configure any of this. You don't install plugins. You don't wire middleware. It's already there the moment the loadout deploys.

**You write logic. The substrate handles everything else.**
