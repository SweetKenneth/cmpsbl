Operations Library

Day-to-day operational procedures for the CMPSBL® Substrate OS.

1. Health Monitoring

1.1 Matrix Integrity

The primary health signal is the Matrix Integrity Score — a weighted sum across all 24 nodes:

matrixIntegrity = Σ(node.health × node.weight)

Grade Scale:
  A ≥ 90  — All systems nominal
  B ≥ 75  — Minor degradation
  C ≥ 60  — Significant degradation (investigate)
  D ≥ 40  — Critical (immediate action)
  F < 40  — System failure (emergency)

1.2 Health Scorecard

The scorecard aggregates multiple dimensions with independent weights. Each dimension reports:

StatusScore RangeAction
healthy70–100No action
degraded40–69Investigate within 1 hour
critical0–39Immediate response required

1.3 Trend Monitoring

The scorecard tracks trend direction from the last 5 readings:

  • improving: current > avg + 3
  • stable: within ±3 of avg
  • declining: current < avg - 3 — investigate before it becomes critical

2.2 Manual Override

// Force close a breaker (use with caution)
import { resetBreaker } from '@/lib/substrate/circuit-breaker';
resetBreaker('module_name');

⚠️ Caution

Manually closing a breaker bypasses the failure threshold. Only do this after confirming the root cause is resolved.

3. Persistence Layer Operations

3.1 Leader Lease

Only one browser tab/instance can be the persistence leader. The leader:

  • Acquires lease on startup
  • Renews every TTL/2 (default: 30s)
  • Performs periodic snapshots every 30 seconds
  • Releases lease on shutdown

3.2 Manual Flush

// Force immediate persistence flush (any instance)
import { flushAll } from '@/lib/control-plane/persistence';
await flushAll();

3.3 Restore to Previous Revision

// List available revisions
import { listRevisions, restoreToRevision } from '@/lib/control-plane/restore';
const revisions = await listRevisions({ limit: 20 });

// Restore to specific revision
await restoreToRevision(revisionId, { replayWalToLatest: false });

🛑 Danger

Restoring to a previous revision overwrites current control plane state. Always verify the target revision before restoring.

4. Incident Response

4.1 Cascade Failure Detected

  1. Check cascade detector output: origin module + chain
  2. Isolate origin module (trip its circuit breaker)
  3. Verify downstream modules recover (breakers should auto-recover)
  4. Investigate root cause in origin module
  5. Reset breaker when root cause is resolved

4.2 Persistence Failure

  1. Check database connectivity
  2. Verify leader lease is held (one instance only)
  3. Check retry backoff status (may be in exponential delay)
  4. Manual flush: flushAll()
  5. If persistent: disable persistence flag, operate in-memory until DB recovers

4.3 SEBA Evolution Failure

  1. Check evolution phase (should be failed or aborted)
  2. Verify rollback snapshot was applied automatically
  3. Check governance gate decision log
  4. Review proposal details for risk assessment errors
  5. Resume SEBA cycles after investigation

6. Graceful Degradation

When a module degrades, the substrate continues operating with reduced integrity. The degradation strategy:

  1. Module failure: Circuit breaker opens → health drops → other modules unaffected
  2. Sector failure: Multiple modules in one sector fail → sector health drops → other sectors continue
  3. Persistence failure: DB unreachable → operate in-memory → retry with backoff → alert
  4. Leader loss: Lease expires → no periodic snapshots → manual flush still works → any instance can become new leader

7. Shutdown Procedure

Shutdown hook priority order:
  1. Control plane persistence flush (highest priority)
  2. Release leader lease
  3. Stop persistence scheduler
  4. Flush telemetry buffer
  5. Close active dispatches (with timeout)

8. Monitoring Checklist (Daily)

  • □ Matrix integrity ≥ 90 (Grade A)
  • □ No circuit breakers in open state
  • □ Persistence leader is held
  • □ Last commit < 60 seconds ago
  • □ WAL queue depth < 1000
  • □ No cascade chains detected in last 24h
  • □ SEBA evolution phase is idle or verified
  • □ CLM budget not exhausted (daily quota check)
  • □ No governance drift alerts
