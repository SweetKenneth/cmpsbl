## 1. Purpose

This document describes the engine stacking strategy: how composable cognitive engines are layered to create increasingly sophisticated capabilities.

## 2. Engine Architecture

### 2.1 Engine Definition

An engine is a packaged, deployable cognitive unit that combines one or more substrate modules with domain-specific configuration, tuned for a specific task class.

### 2.2 Stacking Model

Engines are composable — they can be stacked to create compound capabilities:

```
Base Engine → Enhancement Layer → Domain Specialization → Deployed Engine
```

| Layer | Purpose | Example |
|---|---|---|
| Base | Core cognitive capability | Text understanding |
| Enhancement | Quality or capability augmentation | Memory-augmented understanding |
| Domain | Industry-specific tuning | Legal document understanding |
| Deployment | Runtime configuration | Production SLA-bound deployment |

## 3. Stacking Economics

| Metric | Impact |
|---|---|
| Marginal cost per layer | Decreasing (shared infrastructure) |
| Capability per layer | Increasing (compound capabilities) |
| Pricing per layer | Premium pricing for higher stacks |
| Customer lock-in | Increases with stack depth |

## 4. Strategic Implications

- Stacking creates **natural upsell paths** from base to specialized engines
- Deep stacks are **difficult to replicate** — they require the full substrate infrastructure
- Engine stacking aligns with **enterprise buying patterns** (start simple, add capability)
