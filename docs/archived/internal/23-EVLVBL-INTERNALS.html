4. API Endpoint Architecture

Public API Surface (what customers see):
  POST /v1/wrap     → Input + Schema → Healed result + Stamp
  POST /v1/shadow   → Baseline + Candidate → Match/Diverge + Timing
  POST /v1/probe    → Input + Functions → Probe report
  GET  /v1/rules    → Learned repair rules (project-scoped)
  GET  /v1/metrics  → Health dashboard data
  POST /v1/volver   → Task description → Analysis + Suggestions (Enterprise)

Internal Pipeline (what actually happens server-side):
  1. API Gateway: Key validation, rate limiting, tier enforcement
  2. Input Classification: Archetype detection (injection, empty, malformed)
  3. Schema Validation: Type checking, required field enforcement
  4. Repair Engine: 29+ strategy sequential application
  5. Learning Engine: Rule extraction from successful repairs
  6. Cross-Project Propagation: Anonymized rule sharing across API consumers
  7. Stamp Generation: Cryptographic evolution proof
  8. Response: Healed result + metadata (never internals)
