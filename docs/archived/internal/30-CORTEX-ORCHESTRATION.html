CORTEX Orchestration Internals

Classification: Internal
Epoch: SPARTA (v11.1)
Module: CORTEX (Execution Sector)

1. Overview

CORTEX is the substrate's orchestrator — it coordinates multi-surface workflows without direct surface-to-surface coupling. All complex operations that span multiple execution surfaces are routed through CORTEX.

2. Orchestration Model

Request → CORTEX
  ├── Task decomposition
  ├── Surface dependency resolution
  ├── Parallel dispatch (where possible)
  ├── Sequential chaining (where required)
  ├── Result aggregation
  └── Response composition

2.1 Task Decomposition

CORTEX analyzes incoming requests and decomposes them into surface-level tasks:

Example: "Analyze this code and fix accessibility issues"

Decomposition:
  1. DECODE → Parse natural language intent
  2. INCLUSIVE → Scan code for WCAG violations
  3. ENCODE → Generate fixes for violations
  4. SANDBOX → Test fixes in isolation
  5. VISION → Report results

2.2 Execution Strategies

StrategyWhen UsedBehavior
ParallelTasks have no data dependenciesAll tasks dispatched simultaneously
SequentialTask N depends on Task N-1 outputChained execution with result forwarding
Fan-out/Fan-inMultiple independent tasks feed into aggregationParallel dispatch → wait for all → aggregate

3.1 Timeout Handling

All orchestrations use withTimeout() wrapper:

const result = await withTimeout(
  () => Promise.all(tasks.map(t => dispatch(t))),
  timeoutMs,
  'cortex.orchestrate'
);

On timeout:

  • In-flight tasks are cancelled (where supported)
  • Partial results are returned with timedOut: true flag
  • RIPPLE event emitted: cortex.timeout
  • ECONOMY records partial cost

4. Surface Communication

CORTEX communicates with surfaces exclusively through the RIPPLE event bus — no direct function calls:

CORTEX → RIPPLE.emit('cortex.dispatch', {
  target: 'decode',
  action: 'parse',
  payload: { ... },
  correlationId: 'uuid-v4',
  timeout: 30000
})

Surface → RIPPLE.emit('cortex.result', {
  correlationId: 'uuid-v4',
  success: true,
  data: { ... },
  latencyMs: 150
})

5. Error Handling

Error TypeCORTEX Behavior
Surface unavailableSkip + continue if optional, fail if required
Surface timeoutCancel + return partial results
Surface errorRetry once, then skip/fail based on criticality
All surfaces failedReturn error with full failure report
Orchestration timeoutCancel all in-flight, return partial

5.1 Result Schema

interface OrchestrationResult {
  correlationId: string;
  success: boolean;
  timedOut: boolean;
  results: Map<string, {
    surface: string;
    success: boolean;
    data: unknown;
    latencyMs: number;
    error?: string;
  }>;
  totalLatencyMs: number;
  surfacesInvoked: number;
  surfacesFailed: number;
}
