1. Overview

SANDBOX provides isolated execution environments for safe experimentation, staged deployments, and shadow training. Code executed in SANDBOX cannot affect production state, access external networks, or exceed resource limits.

3. Resource Limits

ResourceDefault LimitConfigurable Range
Execution timeout30s1s – 60s

CPU time10s1s – 30s

Stack depth100 frames50 – 500
Security Invariant: Resource limits are enforced at the runtime level and cannot be overridden by executed code. Exceeding any limit results in immediate termination with a RESOURCE_EXCEEDED error.

4. Snapshot System

4.1 Snapshot Lifecycle

1. PRE-EXECUTION
   → Capture current state (variables, config, registry)
   → Store as immutable snapshot
   
2. EXECUTION
   → Run code in isolated environment
   → Track all state mutations
   
3. POST-EXECUTION
   → Compute diff between pre and post state
   → Generate execution report
   
4. DECISION
   → If approved: apply diff to production
   → If rejected: discard diff (snapshot unchanged)

7. Integration with EVOLUTION

SANDBOX is the execution backend for all EVOLUTION shadow training:

EVOLUTION.scan()
  → Gap identified
  → IMMUNITY creates shadow probe
  → SANDBOX executes probe in isolation
  → Results compared to baseline
  → If improved: ENCODE absorbs as rule
  → If degraded: logged as failed attempt
