Economy & Metering Internals

Classification: Internal
Epoch: SPARTA (v11.1)
Module: ECONOMY (Execution Sector)

1. Overview

The ECONOMY module provides value-aware cost tracking, ROI calculation, and usage metering across the substrate. It answers two questions: "How much did that cost?" and "Was it worth it?"

2. Cost Model

2.1 Cost Record Schema

interface CostRecord {
  id: string;                // UUID
  timestamp: number;         // Unix ms
  category: string;          // e.g., "ai.inference", "compute.sandbox"
  module: string;            // Originating module
  tokensUsed: number;        // Token count (clamped 0–10M)
  computeTimeMs: number;     // Wall clock (clamped 0–3.6M)
  costMillicents: number;    // Cost in 1/1000 of a cent (clamped 0–1M)
  provider: string;          // e.g., "openai", "google"
  model: string;             // e.g., "gpt-5", "gemini-2.5-pro"
  metadata: Record;          // Additional context
}

3. ROI Calculation

ROI is calculated per operation and aggregated per module:

ROI = (value_generated - cost_incurred) / cost_incurred × 100

3.1 Value Attribution

Value SourceMeasurement
Task completionPredetermined value per task type
Learning gainSkill progression delta × base value
Error preventionEstimated cost of undetected error
OptimizationPerformance improvement × request volume

4. Usage Metering Pipeline

Operation Execution
  → Cost record created (ECONOMY)
  → Quota check (ACCESS zone)
  → Usage log appended (access_usage table)
  → Daily quota updated (access_quotas table)
  → If over quota: rate limit enforced
