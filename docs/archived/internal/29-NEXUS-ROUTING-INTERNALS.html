NEXUS Routing Internals

Classification: Internal
Epoch: SPARTA (v11.1)
Module: NEXUS (Execution Sector)

1. Overview

NEXUS is the AI routing gateway — the single entry point for all AI inference requests. It abstracts provider differences, manages fallback chains, and ensures optimal model selection based on task requirements, cost constraints, and provider health.

2. Routing Architecture

Incoming AI Request
  → DEFENSE overlay (rate limiting)
  → ACCESS zone (API key + quota validation)
  → NEXUS Router
    ├── Task classification
    ├── Provider selection (health-weighted)
    ├── Model selection (capability-matched)
    ├── Cost estimation
    └── Dispatch + fallback chain
  → Provider API
  → Response normalization
  → ECONOMY (cost recording)
  → Caller

3.1 Provider Health Tracking

Each provider maintains a health score updated on every request:

interface ProviderHealth {
  provider: string;
  healthScore: number;      // 0.0–1.0
  successRate: number;       // Rolling 100-request window
  avgLatencyMs: number;      // Rolling average
  lastFailure: number | null;
  consecutiveFailures: number;
  circuitState: 'closed' | 'half-open' | 'open';
}

4. Model Selection Algorithm

1. Parse task requirements:
   - Complexity (simple / moderate / complex / expert)
   - Modality (text / multimodal / vision / code)
   - Context length (short / medium / long / massive)
   - Cost sensitivity (low / medium / high)

2. Filter eligible models:
   - Must support required modality
   - Must handle required context length
   - Provider must be healthy (circuit closed or half-open)

3. Rank by composite score:
   score = (capability_match × 0.4) +
           (provider_health × 0.3) +
           (cost_efficiency × 0.2) +
           (latency_score × 0.1)

4. Select top-ranked model
5. Build fallback chain from remaining eligible models

5. Fallback Chain

Every request includes a fallback chain of alternative models:

Primary: gemini-2.5-pro (Google)
  → Fallback 1: gpt-5 (OpenAI)
    → Fallback 2: gemini-2.5-flash (Google)
      → Fallback 3: gpt-5-mini (OpenAI)
        → Hard fail: return error to caller

6. Response Normalization

All provider responses are normalized to a unified schema:

interface NexusResponse {
  content: string;           // Generated text
  model: string;             // Actual model used
  provider: string;          // Actual provider used
  tokensUsed: {
    input: number;
    output: number;
    total: number;
  };
  latencyMs: number;
  fallbackUsed: boolean;     // True if primary failed
  fallbackChain: string[];   // Models attempted
  costMillicents: number;    // Estimated cost
}
