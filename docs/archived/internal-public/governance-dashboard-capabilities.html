1. Overview

The Governance Dashboard (/admin/patches) is the single control plane for managing what gets synchronized from the CMPSBL® substrate to the LNCHBL distribution. Since both projects share the same backend infrastructure, "dispatch" operations update the shared database directly — there is no remote HTTP call.

Key principle: CMPSBL is the canonical authority. LNCHBL receives only what the Governor explicitly approves. No automatic synchronization occurs.

2. Patch Authoring

Create structured patch records that define what capabilities, engines, and tier access levels are available in LNCHBL.

FieldDescriptionRequired
versionSemantic version string (e.g., 2.1.0)Yes
required_tierMinimum tier to access: FREE BUILDER PROYes
enginesComma-separated engine identifiers to unlockNo
capabilitiesComma-separated capability identifiers to unlockNo
changelogHuman-readable description of what this patch enablesYes

Validation Rules

  • Target distribution is always LNCHBL (hardcoded)
  • Version string must be non-empty
  • Changelog must be non-empty
  • No pf-* function references are permitted (CMPSBL-only prefix)
  • Protected fields (distribution_id, identity, canon_authority, federation_enabled, self_evolution, self_improvement) cannot be overridden

3. Patch Lifecycle Management

Every patch follows a three-state lifecycle:

StateBadgeActions Available
DraftDRAFTPublish, Edit (future)
PublishedPUBLISHEDUnpublish (→ Draft), Revoke
RevokedREVOKEDView only (terminal state)

What You Can Do

  • Author Patch: Create a new draft patch with version, tier, engines, capabilities, and changelog
  • Publish: Move a draft to published — makes it visible to LNCHBL consumers
  • Unpublish: Revert a published patch back to draft without revoking
  • Revoke: Permanently mark a patch as revoked — it cannot be re-published
  • View Manifest: Inspect the signed JSON manifest for any patch

4. Governance Stream

The Governance tab provides a real-time feed of substrate changes with an approve/decline workflow.

Change Statuses

StatusMeaning
PENDINGChange recorded, awaiting Governor review
APPROVEDGovernor approved for inclusion in LNCHBL
DECLINEDPermanently excluded from LNCHBL (with reason)
DISPATCHEDApproved and marked as synchronized

What You Can Do

  • Filter: View changes by status (All, Pending, Approved, Declined, Dispatched)
  • Approve: Mark a pending change for inclusion in LNCHBL
  • Decline: Reject a change with a reason (e.g., "CMPSBL-only change")
  • Batch Dispatch: Push all approved changes to dispatched status in one action
  • Real-time Updates: Changes stream in via WebSocket — no manual refresh needed

Change Metadata

Each change record includes:

  • title and description — human-readable summary
  • files_changed — array of file paths affected
  • diff_summary — structured diff data
  • commit_hash and author — git provenance
  • source — origin system (substrate, manual, etc.)

5. Substrate Export

The Export Substrate ZIP button generates a complete SPARTA v11 architecture package for LNCHBL.

What's Included

Usage Protocol

  1. Download the ZIP from the Governance tab
  2. In the LNCHBL project, delete all paths listed in CLEANUP_MANIFEST.json
  3. Extract the ZIP into the LNCHBL project root
  4. Run migrations and deploy edge functions

6. Download Analytics

  • Recent Activity: Last 10 downloads with patch ID, tier, and timestamp

7. Security Invariants

Canon Lock: The dashboard enforces that no patch can modify CMPSBL's canonical identity, authority flags, or governance configuration. These fields are permanently blocked at both the client validation layer and the database level.

Protected Fields (Cannot Be Overridden)

  • distribution_id
  • identity
  • canon_authority
  • federation_enabled
  • self_evolution
  • self_improvement

Blocked Patterns

  • Any function name starting with pf- (CMPSBL internal prefix)
  • Any file path containing distribution.ts or canon
  • Any attempt to modify the lnchbl-manifest.ts registry
