🔐 06 — SEBA (Self-Evolving Bounded Agent)

v2.1.0 — Full Spectrum Autonomy Pipeline

Architecture

9 Analysis Engines → Proposal Generation → Governance Gate → Execution

Core 4: Memory, Learning, Imagination, Reasoning
Extended 5: Security, Telemetry, Governance, Resources, Architecture

Sub-modules:
  - CognitiveAnalyzer — Scans for improvement opportunities
  - ProposalGenerator — Creates typed improvement proposals
  - GovernanceGate — Evaluates safety/coherence/ethics
  - EvolutionExecutor — Shadow→production execution
  - ProposalStore — Database persistence
  - EvolutionStampGenerator — Traceability stamps
  - LLMAnalyzer — AI-enhanced impact prediction

5 Operating Modes

ModeBehavior
offSEBA disabled
observeScans and logs proposals only
advisoryProposes improvements, requires human approval (DEFAULT)
governedAuto-executes if governance approves AND confidence ≥ threshold
autonomousFull autonomy within bounds (requires explicit unlock)

SEBA Cycle (5 Phases)

Phase 1: COGNIZING
  - CognitiveAnalyzer runs 9 analysis engines
  - Produces CognitiveInsight[] (type, confidence, urgency, evidence)
  - If no insights → cycle ends early

Phase 2: PROPOSING
  - ProposalGenerator converts insights to ImprovementProposal[]
  - Each proposal: category, risk_level, confidence_score, proposed_actions
  - Persisted to database via ProposalStore.storeBatch()

Phase 3: EVALUATING → GATING
  - GovernanceGate.evaluate(proposal)
  - Checks: coherence_score, ethical_score, risk_assessment, safety_score
  - Decision: approve | approve_with_conditions | defer | reject | escalate

Phase 4: APPLYING
  - Only if canAutoExecute() OR mode=autonomous
  - EvolutionExecutor runs shadow → production pipeline
  - Creates EvolutionStamps for traceability
  - Updates proposal status in database

Phase 5: VERIFYING
  - Health delta check
  - If health_delta < -max_health_degradation → auto-rollback

Rollback

Atomic rollback captures 4 snapshots before any change:

  1. Config snapshot — all module configurations
  2. Prompt snapshot — all active system prompts
  3. Weight snapshot — all routing/scoring weights
  4. Rule snapshot — all defense and governance rules

Partial rollback deliberately NOT supported to prevent inconsistent state.
