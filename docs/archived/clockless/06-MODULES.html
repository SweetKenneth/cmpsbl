1. DECODE

LayerCognitive
PurposeIntent router and system voice
Sourcesrc/lib/substrate/decode/

DECODE parses human ambiguity into structured task packets. It understands context, personality profiles, and multi-turn conversations. Output is consumed by ENCODE for execution. DECODE is the primary user-facing interaction surface.

2. ENCODE

LayerOrchestration
PurposeCode generation and transformation engine
Sourcesrc/lib/substrate/encode-module/

ENCODE is the implementation executor — the hands that touch, polish, and modify the substrate. It accepts structured task packets from DECODE and generates code across 6 target surfaces: code, UI, docs, database, edge functions, and tests. All output has confidence scoring and diff preview before application.

3. VISION

LayerOperational
PurposeUnified analytics and observability
Sourcesrc/lib/substrate/telemetry-engine.ts

VISION provides real-time metrics, telemetry collection, and observability dashboards. It tracks module health, performance characteristics, event throughput, and system-wide trends. All telemetry flows through VISION for aggregation and presentation.

4. CORTEX

LayerOrchestration
PurposePipeline orchestrator
Sourcesrc/lib/substrate/orchestrator-engine.ts

CORTEX manages multi-stage cognitive workflows and engine composition. It defines preset pipelines, coordinates engine execution order, and manages the world model. It provides the foundation for synergy pipelines that combine multiple modules.

5. NEXUS

LayerOrchestration
PurposeMulti-provider AI gateway
Sourcesrc/lib/nexus/

NEXUS intelligently routes AI requests across multiple providers (OpenAI, Anthropic, Google, etc.) based on capability matching, cost optimization, latency requirements, and provider health. It provides a unified interface regardless of the underlying provider.

6. ECONOMY

LayerInfrastructure
PurposeCost attribution and budgeting
Sourcesrc/lib/substrate/economy-module/

ECONOMY tracks real-time cost attribution across all AI operations, provides budgeting controls, marketplace signaling, and usage forecasting. Every API call, token, and compute cycle is attributed to a module, task, or user.

7. SANDBOX

LayerInfrastructure
PurposeIsolated execution environments
Sourcesrc/lib/substrate/sandbox-module/

SANDBOX provides isolated execution environments for safe code execution, speculative runs, and evolution testing. Mutations proposed by the EVOLUTION mesh are tested in SANDBOX before promotion to production. Each sandbox is ephemeral and has no side effects on the live system.

8. INCLUSIVE

LayerOperational
PurposeAccessibility and WCAG compliance
Sourcesrc/lib/inclusive/

INCLUSIVE scans for accessibility issues, enforces WCAG compliance standards, and ensures inclusive design across all user-facing surfaces. It provides automated remediation suggestions and tracks compliance scores over time.
