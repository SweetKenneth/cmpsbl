Governance & Boundaries

How Clockless enforces safe operation through capability gating, namespace discipline, veto authority, and deterministic boundary enforcement.

Clockless v12 • Confidential

Enforcement Model

Clockless governance is not advisory — it is enforced at the execution layer. Every command, state transition, and capability activation passes through governance checks before execution. There are no bypass mechanisms.

The governance pipeline consists of:

  1. Policy Evaluation — The Governance Guard evaluates incoming operations against active policies
  2. Veto Check — Any module may have issued a standing veto that blocks specific operations
  3. Epistemic Validation — Response content is validated for provenance and factual grounding
  4. Scope Matrix — Operations are matched against the scope matrix to ensure module-level authorization
  5. Transition Validation — State changes require quorum approval with configurable thresholds

Namespace Discipline

Every command in the substrate follows strict namespace conventions:

  • Format: module.action (e.g., memory.store, nexus.route)
  • Modules may only register handlers under their own namespace
  • Cross-module calls flow through the Engine Bus — no direct function imports between modules
  • Namespace collisions are rejected at registration time

This ensures clean dependency boundaries and makes the system auditable at the command level.

Veto Authority

The veto system provides a safety mechanism for blocking unsafe operations:

Veto Lifecycle

  1. Issue — A module detects an unsafe condition and issues a veto request with scope and severity
  2. Evaluate — The Governance Bridge evaluates the veto against precedent and current system state
  3. Enforce — Approved vetoes are applied immediately and block matching operations
  4. Decay — Vetoes have entropy-based decay; they expire unless reinforced by continued signals
  5. Revoke — Vetoes can be explicitly revoked when the triggering condition is resolved

Unknown Command Handling

When the Engine Bus receives a command for an unregistered namespace or action:

  1. The command is rejected with a structured error (not silently dropped)
  2. The rejection is logged in the telemetry stream with full context
  3. The INTENT field attempts fuzzy matching to suggest the intended command
  4. If the command appears to target a disabled or unactivated capability, the response includes the required entitlement

There is no "catch-all" handler. Unknown commands never execute.

Why This Is Not Remote Shell

Clockless terminal is a governed command interface, not a remote shell.

Key distinctions:

  • No filesystem access — Commands operate on substrate state, not operating system resources
  • No arbitrary code execution — Only registered handlers execute, within governance boundaries
  • Full audit trail — Every command, result, and side effect is recorded
  • Governance pipeline — Every command passes through policy evaluation before execution
  • Scoped authorization — Commands are authorized against the user's entitlements and the module's scope matrix

Compliance Monitoring

The compliance auditor runs continuously and produces:

  • Compliance Score — Weighted aggregate across all governance rules
  • Violation Reports — Specific policy violations with severity and remediation guidance
  • Drift Detection — Statistical analysis of governance state changes over time windows
  • Trend Analysis — Historical compliance scores for regression detection
