Layered Architecture

The runtime is organized into five concentric topology layers, each with distinct responsibilities:

Shell:   DEFENSE (outer containment boundary)
Plane:   GOVERNANCE (supervisory blanket)
Fields:  EVOLUTION, IMMUNITY, INTENT (transformation fabric)
Spine:   CORE → SYSTEM → BRAIN / MEMORY / DREAM
Grid:    OCG — RIPPLE, ACCESS, IDENTITY, RELAY, AUDIT
Branch:  Execution — DECODE, ENCODE, VISION, CORTEX, NEXUS,
         ECONOMY, SANDBOX, INCLUSIVE, INTEGRATION

The Spine carries the vertical boot and cognition flow. The OCG enforces operational compliance boundaries. Execution nodes perform specialized processing. Fields permeate the entire runtime with evolution, resilience, and capability discovery. The Shell and Plane wrap all layers with defense containment and governance policy enforcement.

Command Routing

Every operation in Clockless flows through the Engine Bus, a centralized command dispatch layer:

  1. A command arrives (terminal input, API call, internal trigger)
  2. The Engine Bus resolves the target node namespace
  3. Governance Guard evaluates the command against active policies
  4. If approved, the command is dispatched to the target handler
  5. The handler executes and returns a CommandResult
  6. Telemetry records the execution trace
  7. The result propagates through RIPPLE if event listeners are registered

Namespace Resolution

Commands follow a strict module.action namespace convention:

memory.store     → MEMORY node, store handler
nexus.route      → NEXUS node, route handler
defense.scan     → DEFENSE node, scan handler
governance.audit → GOVERNANCE plane, audit handler

Handler Registration Flow

Each node registers its handlers during the boot sequence:

  1. CORE boots first and establishes the handler registry
  2. Spine nodes register (SYSTEM → BRAIN → MEMORY → DREAM)
  3. OCG nodes register (RIPPLE → ACCESS → IDENTITY → RELAY → AUDIT)
  4. Execution nodes register (order determined by dependency graph)
  5. Fields register (EVOLUTION → IMMUNITY → INTENT)
  6. GOVERNANCE plane registers (reads all registered handlers for policy enforcement)
  7. DEFENSE shell registers last (wraps all outbound paths)

Registration is idempotent. Duplicate handler registration replaces the existing handler with an audit log entry.

State & Memory Model

State Engine

The State Engine maintains schema-validated runtime state for all modules. Each state field has a declared type, default value, and validation rule. State mutations are atomic and trigger RIPPLE events.

Memory Core

Memory in Clockless is tiered:

Failure Discipline

Every node in the runtime implements a circuit breaker with four states:

StateBehaviorHealth Impact
closedNormal operationRaw health value
half-openProbe requests onlyCapped at 50
openAll requests rejectedForced to 0
reroutingFailover to backup handlerCapped at 85

Breaker transitions are governed by failure thresholds and emit RIPPLE events for observability. CORE node failure triggers a CRITICAL system status regardless of other node health.
