Artifact Philosophy

Clockless capabilities are not sold as individual features. They are delivered as Artifact Packs — pre-composed bundles that each require at least one substrate-native construct impossible to replicate with fragmented SaaS tools.

Every pack contains an internal Emergence Clause that justifies its architectural reliance on the unified runtime. This ensures that each artifact expresses genuine emergent system behavior (feedback loop detection, resource contention arbitration, autonomous pattern consolidation) rather than simple feature bundling.

Slot Capacity Model

Artifact packs are governed by a slot-based activation model:

ConceptDescription
SlotA single activation unit. Each pack consumes exactly one slot.
Slot CapacityTotal slots available to a user, determined by subscription tier.
Active CountCurrently activated packs. Must be ≤ slot capacity.
Equal-Pack DoctrineAll packs cost the same activation weight (1 slot). Differentiation is in emergent density, not pricing tiers within packs.

Activation RPC Flow

Pack activation follows a deterministic RPC sequence:

  1. Request — User selects a pack for activation via the Depot interface
  2. Entitlement Check — ACCESS module verifies: valid subscription, available slots, no conflicting activations
  3. Governance Gate — GOVERNANCE plane evaluates activation against compliance rules
  4. Activation RPC — The backend RPC (activate_capability_pack) atomically updates the activation record
  5. Audit Log — An activation event is recorded in the AUDIT module with full context
  6. Pipeline Wiring — The pack's crystallized pipelines are registered with the Engine Bus
  7. Confirmation — User receives activation confirmation with active slot count

Deactivation

Deactivation follows the same flow in reverse, with an additional cooldown period to prevent rapid toggling that could destabilize pipeline state.

Entitlement Guarding

Every capability execution checks entitlements at runtime:

// Simplified entitlement check flow
1. Extract user_id from session
2. Query active_packs for user
3. Check if requested capability_id belongs to an active pack
4. If not entitled → reject with structured error
5. If entitled → execute and meter usage

Entitlement checks are cached with short TTLs to minimize database round-trips while maintaining accuracy.

Crown Jewel Strategy

A subset of packs are designated Crown Jewels — the highest-density emergent expressions in the system. These packs:

  • Require multiple crystallized pipelines operating across 3+ modules
  • Express behaviors that compound over time (learning, adaptation, self-improvement)
  • Have the highest differentiation scores in the asset scoring model
  • Are protected by additional governance oversight during activation

Asset Scoring Formula

Each pack is scored using a weighted formula:

score = (emergent_density × 0.28)
      + (substrate_reliance × 0.24)
      + (user_value × 0.24)
      + (compounding_potential × 0.24)

The increased differentiation weighting (0.28) prioritizes packs that express behaviors unique to the unified substrate architecture.
