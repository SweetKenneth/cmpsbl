How Clockless monetizes infrastructure through subscription tiers, slot-based activation, the equal-pack doctrine, and usage-based metering.

Baseline vs. Activated Capabilities

Every Clockless instance includes a baseline capability set available to all users regardless of tier:

  • Core runtime (all 24 nodes operational)
  • Terminal interface with full command routing
  • Basic memory (session-scoped + limited persistence)
  • Single-provider AI routing
  • Standard governance enforcement
  • Basic observability dashboard

Activated capabilities are unlocked through Artifact Pack activation and expand the runtime with advanced emergent behaviors, multi-provider routing, extended memory tiers, and cross-domain orchestrations.

Slot Scaling Model

Slot capacity determines how many Artifact Packs a user can have active simultaneously:

Scaling Rules

  • Each pack consumes exactly 1 slot (equal-pack doctrine)
  • Slots are fungible — any pack can occupy any slot
  • Activation/deactivation is instant (no provisioning delay)
  • Inactive packs retain their configuration for re-activation
  • Slot count increases with tier upgrades and is prorated

Equal-Pack Doctrine

All packs have equal activation weight regardless of their internal complexity or capability density. This design decision serves three purposes:

  1. Simplicity — Users understand exactly what "1 slot" means
  2. Fair comparison — Packs compete on capability value, not pricing manipulation
  3. Predictable economics — Upgrade path is clear: more slots = more capabilities

Differentiation between packs occurs in the asset scoring model, not in activation cost. Crown Jewel packs express higher emergent density but still consume 1 slot.

Expansion Strategy

Revenue growth follows a land-and-expand model:

  1. Land — Free tier provides enough value to demonstrate substrate benefits
  2. Activate — Users activate their first pack and experience emergent capabilities
  3. Expand — Increasing pack activation drives tier upgrades for more slots
  4. Enterprise — Organizations adopt federated instances with custom governance
