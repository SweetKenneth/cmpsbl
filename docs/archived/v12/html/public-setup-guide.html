What is Clockless?

Clockless is a cognitive infrastructure platform that combines an AI-powered runtime with a continuously learning engine. Once deployed, the system autonomously improves its knowledge, monitors its own health, and surfaces actionable recommendations — all while enforcing strict safety boundaries.

Key Capabilities

  • Continuous Learning: The system studies relevant topics around the clock, building expertise in areas like security, code quality, reliability, and accessibility.
  • System Health Scanning: A multi-source scanning engine checks for technical debt, security gaps, accessibility issues, compliance gaps, and structural integrity.
  • Governed Evolution: When the system is stable, it generates improvement proposals. All changes require human approval — the system never self-mutates.
  • Tiered Memory: Knowledge is stored in a multi-tier memory model that automatically manages capacity, decays stale data, and surfaces relevant information when needed.
  • Multi-Provider AI Routing: The NEXUS router intelligently distributes AI requests across multiple providers for cost efficiency, reliability, and failover.

Installation

1

Clone & Install

git clone <repo-url>
cd clockless
bun install

Requires Node.js 18+ or Bun 1.0+.

2

Start Development Server

bun run dev

The application starts at http://localhost:5173. All backend connections are configured automatically by Clockless Cloud.

3

Add AI Provider Keys

To enable the learning engine (CLM), you need at least one AI provider API key. Add it through the Clockless Cloud secrets manager:

ProviderHow to Get a Key
OpenAIplatform.openai.com/api-keys
Anthropicconsole.anthropic.com
Google AIaistudio.google.com/apikey

You can add multiple providers for redundancy and cost optimization. The system automatically routes to the best available provider.

4

Verify CLM is Running

Open the terminal in the application and type:

clm.status

You should see the CLM status showing enabled: true and budget information. If you see errors, verify your API key is configured correctly.

That's it! No manual environment configuration is needed. Clockless Cloud provides all database connections, backend functions, and infrastructure automatically.

How the Learning Engine Works

The Clockless Learning Engine (CLM) is an always-on system that continuously builds expertise across your substrate's modules. Here's what to expect:

What It Studies

CLM maintains a curated curriculum covering every major area of the system. Topics range from security best practices and code patterns to accessibility standards and API cost optimization. The system prioritizes topics based on:

  • Priority weight: Critical areas (architecture, security, code quality) are studied first
  • Knowledge gaps: Areas where the system has less expertise get more attention
  • Spaced repetition: Previously studied topics are revisited at optimal intervals for long-term retention
  • External sources: The system can study real-world documentation and research papers during "deep dive" cycles

Budget & Rate Limiting

Learning is budget-governed to prevent runaway costs:

  • Budget is dynamically allocated in 4-hour cycles based on available API capacity
  • A configurable quiet hours window (default: 3am–5am) pauses learning
  • Consecutive failures trigger automatic backoff, and 5+ failures auto-pause the engine
  • You can always check remaining budget with clm.status

What Happens to Learned Knowledge

Insights from each learning cycle are:

  1. Stored in the substrate's tiered memory system
  2. Connected to a knowledge graph linking topics to modules
  3. Periodically consolidated during "dream cycles" that synthesize cross-domain insights
  4. Surfaced in system reports and evolution proposals

System Scanning

Clockless continuously monitors its own health through a multi-source scanning engine. Scans check for:

AreaWhat It Checks
Structural IntegrityModule health, node connectivity, contract compliance
Technical DebtCode quality issues, architectural smells, outdated patterns
SecurityThreat detection, IP reputation, authentication flows
AccessibilityWCAG compliance, missing labels, navigation issues
ComplianceAudit chain integrity, policy coverage
PerformanceAPI latency, memory utilization, circuit breaker state

Reading Scan Reports

Scan reports follow a consistent format:

  • Executive Summary: Overall health grade and key findings
  • Action Plan: Up to 5 prioritized steps, balanced between debt elimination (60%) and system evolution (40%)
  • Evolution Opportunities: When the system is fully stable, the scanner automatically identifies opportunities for improvement
Stable systems always evolve. If a scan shows zero critical issues across all layers, the system guarantees at least one evolution recommendation. This ensures continuous improvement even when everything is healthy.

Evolution & Upgrades

Clockless generates improvement proposals but never applies them automatically. Every change requires explicit human approval. The process works like this:

  1. The scanning engine identifies improvement opportunities
  2. A detailed proposal is generated with specific, actionable steps
  3. You review the proposal and approve or reject it
  4. Approved proposals are applied by the external AI execution system
  5. Results are verified and recorded

This "human-in-the-loop" approach ensures you maintain full control over what changes are made to your system.

  • An initial health scan runs automatically
  • Memory tiers begin populating with learned insights

  • Spaced repetition kicks in, revisiting earlier topics for consolidation

Frequently Asked Questions

Do I need to keep the browser open for learning to work?
No. The primary learning engine runs server-side and operates 24/7 regardless of whether a browser is open. Having a browser tab open provides additional supplementary learning capacity.
How much does the learning engine cost in API usage?
Costs depend on your tier and the AI providers you've configured. The budget governor ensures spending never exceeds your configured limits, and the system optimizes routing for cost efficiency.
Can the system make changes without my approval?
No. All evolution proposals require explicit human approval before they are applied. The system will never modify its own code or configuration autonomously.
What happens if my API key runs out of credits?
Learning cycles will fail, trigger automatic backoff, and eventually auto-pause after 5 consecutive failures. The rest of the system continues operating normally. Once your API key has credits again, resume with clm.resume.
Can I run Clockless without the learning engine?
Yes. You can disable CLM entirely with clm.disable. The substrate's operational features (authentication, database, scanning) work independently. You just won't get continuous knowledge building or spaced repetition.
How do I add more AI providers?
Add provider API keys through the Clockless Cloud secrets manager. The system automatically detects new providers and includes them in the routing pool. No code changes needed.
What's the "kill switch" for?
The kill switch (clm.kill) is an emergency stop that immediately halts all learning activity. Use it if you notice unexpected behavior or want to pause all AI spending instantly. Undo with clm.unkill.
How do I see what the system has learned?
Use clm.status to see mastery scores, budget usage, and queue sizes. The knowledge graph and memory tiers are also visible through the VISION dashboard.
