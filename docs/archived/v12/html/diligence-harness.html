Diligence Harness

The Clockless test battery, surface commands, failure discipline, severity model, and how to interpret verification results.

Clockless v12 • Confidential

Test Battery Overview

The diligence harness is the Clockless verification system that validates runtime integrity across all 24 nodes, governance enforcement, capability registration, and cross-module communication. It is not a unit test suite — it is a production integrity verification system.

The battery operates at four levels:

LevelWhat It TestsFrequency
Boot VerificationAll nodes register, weights sum to 1.0, dependency graph resolvesEvery cold start
Handler ParityEvery registered command has a corresponding handler, no orphansOn registration change
Governance CoherencePolicy engine evaluates correctly, vetoes enforce, transitions validateContinuous
Integration SmokeCross-module dispatch works, Engine Bus routes correctly, events propagateOn demand / CI

Surface Commands

The diligence harness is accessible through the terminal interface:

system.diligence              # Run full battery
system.diligence --level boot # Boot verification only
system.diligence --level parity
system.diligence --level governance
system.diligence --level smoke
system.diligence --report     # Generate printable report
system.health                 # Quick matrix integrity check

Failure Discipline

When the harness detects a failure:

  1. Classify — The failure is assigned a severity level (see below)
  2. Isolate — The affected node's circuit breaker transitions to half-open or open
  3. Report — A structured failure report is emitted via RIPPLE and logged to AUDIT
  4. Remediate — If auto-remediation is available (e.g., handler re-registration), it executes
  5. Verify — After remediation, the specific test re-runs to confirm resolution

Failures are never silently swallowed. Every failure produces an audit trail regardless of whether remediation succeeds.

How to Interpret Results

Diligence reports follow a consistent structure:

Report Structure

{
  "timestamp": "2026-02-27T...",
  "level": "boot | parity | governance | smoke",
  "status": "PASS | FAIL | DEGRADED",
  "total_checks": 142,
  "passed": 140,
  "failed": 2,
  "severity_summary": {
    "critical": 0,
    "error": 1,
    "warning": 1,
    "info": 0
  },
  "failures": [
    {
      "check": "handler_parity.decode.interpret",
      "severity": "error",
      "message": "Handler registered but response shape mismatch",
      "remediation": "auto | manual",
      "resolved": false
    }
  ],
  "matrix_integrity": {
    "operational": 94,
    "structural": 100,
    "status": "MATRIX STABLE"
  }
}

Reading the Report

  • PASS — All checks passed. System is operating within expected parameters.
  • DEGRADED — Some checks failed but no CRITICAL issues. System is operational with reduced capability.
  • FAIL — At least one CRITICAL failure. System requires immediate attention.

The matrix_integrity section provides a real-time snapshot of the weighted node health. An operational score below 80 indicates MATRIX DEGRADED status. Below 40 is CRITICAL.
