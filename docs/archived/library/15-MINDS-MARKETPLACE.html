1. Architecture Overview

The Minds system operates in two execution modes with a strict boundary between learning and production:

INTERNAL_LEARNING

  • CLM (Continuous Learning Mode) enabled
  • Tools are mutable — can be added/removed
  • Memory evolves across sessions
  • Performance scored and drift-detected
  • Auto-rollback on degradation (<0.3 score)
  • Never exposed publicly

PUBLIC_STABLE

  • CLM disabled
  • Snapshot-frozen — tools, config, and memory schema are immutable
  • Version-tagged (v1.0, v1.1, etc.)
  • Integrity-verified via SHA-256 hash
  • Upgrade only via explicit migration

Key principle: No public Mind ever runs in live learning mode. Public Minds are always snapshot clones of internally trained agents.

4. Tool Binding System

Every Mind has a governed tool registry with four classes:

Tool ClassPurposeExamples
core_cognitionMemory read/write, task execution — every Mind gets theseMemory Read, Memory Write, Task Execute
role_specificDomain-specialized tools bound to a Mind's rolePipeline Tracker (Sales), STRIDE Modeler (Security)
open_sourceOpen-source integrations the Mind can leverageWeb search, document parser, code linter
substrateInternal platform tools (never exposed publicly)CLM hooks, drift detector, snapshot manager

Tool Governance Rules

RuleValue
Max tools per Mind24 (paid/internal) · 8 (free)
Default timeout30 seconds (execute tools: 60s)
Circuit breakerEnabled on all tools
Failure isolationTool failure cannot crash the Mind
Sandbox safetyAll tools run in sandboxed scope
RevocabilityRole-specific and open-source tools can be revoked without breaking stability
Audit trailAll tool invocations logged with trace ID

Default Core Tools (All Minds)

Memory Read   → read from memory partition (memory:{sku})
Memory Write  → write to memory partition (memory:{sku})
Task Execute  → execute a task in the Mind's scope (task:{sku})

5. Versioning & Snapshots

Each Mind maintains a version lineage with two branches:

Internal Branch

  • Runs CLM — continuously evolving
  • Tools and scope can change
  • Not exposed publicly
  • Learning deltas logged and scored

Stable Branch

  • Snapshot-frozen from internal branch
  • Immutable once released
  • Versioned: v1.0, v1.1, etc.
  • Integrity-verified (SHA-256)
  • Upgradeable only via explicit migration

Snapshot Contents (Frozen)

FieldDescription
frozenConfigCapability profile at time of snapshot
frozenToolBindingsExact tool set — locked, cannot change
frozenMemorySchemaMemory partition structure — locked
frozenCapabilityProfileTier, memory depth, tool count limits
integritySHA-256 hash for tamper detection
immutableAlways true — cannot be edited post-release

6. CLM Safety Constraints

Continuous Learning Mode runs only on internal agents. The safety policy enforces:

ConstraintWhat It Prevents
Tool Modification BlockedCLM cannot add, remove, or alter tool definitions
Security Boundary LockedCLM cannot change permission scopes or access levels
Scope Escalation BlockedCLM cannot grant itself broader capabilities
Restricted URL BlockedCLM cannot access URLs outside its whitelist
Learning Delta LoggingEvery learning step is recorded with score
Performance ScoringEvery action is scored for quality tracking
Drift DetectionScore drops below 0.3 trigger alerts
Auto-RollbackDegradation triggers automatic rollback to last good state
