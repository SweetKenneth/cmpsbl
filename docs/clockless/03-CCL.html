1. Overview

CCL (Clockless Cognitive Lucidity) is the Layer 1 infrastructure convergence layer. It consolidates all cross-cutting infrastructure services — event routing, authentication, API management, webhook delivery, and compliance logging — into a unified initialization and health surface.

2. Absorbed Modules

2.1 RIPPLE → Signal Subsystem

The event bus. Module event emission, subscription routing, pub/sub messaging. All inter-module communication flows through Signal. Legacy commands: ripple.emit, ripple.status.

2.2 ACCESS → Access Subsystem

API key management, rate limiting, entitlements, usage metering, and the product catalog. Controls who can call what, how often, and at what cost. Legacy commands: access.status, access.keys.

2.3 IDENTITY → Identity Subsystem

Session management, actor resolution, trust scoring, and cross-agency portability. Every action in the substrate has provenance traced through Identity. Legacy commands: identity.session, identity.resolve.

2.4 RELAY → Relay Subsystem

Outbound webhook delivery with HMAC signing, retry logic (exponential backoff), delivery analytics, and outbound routing. Legacy commands: relay.deliver, relay.status.

2.5 AUDIT → Audit Subsystem

Immutable, cryptographically-chained compliance logging. Every significant action produces an audit entry that is append-only and tamper-evident. AUDIT was moved from a public module into CCL because compliance logging is infrastructure, not a user-facing capability. Legacy commands: audit.status, audit.query.

4. Initialization Sequence

initializeCCL()
  ├── initializeIdentity()    → session management, actor resolution
  ├── initializeAccess()      → API keys, rate limiting, entitlements
  ├── initializeSignal()      → event bus, subscription routing
  ├── initializeRelay()       → webhook delivery, HMAC signing
  ├── initializeAudit()       → compliance logging, cryptographic chains
  └── bindHealthCheckSurface() → read-only integrity binding

Each subsystem initializer sets its health to 100 and emits a success event. If any initializer throws, the entire CCL boot is marked as failed but the system continues in degraded mode.

7. Health Check Integration

The Substrate Health Check binds to CCL via the integrity subsystem. This is the only read surface in the entire CCL layer. It validates:

  1. Registry shape — all expected modules are declared
  2. Route integrity — critical routes resolve
  3. Pipeline crystallization — 100 pipelines have valid shape
  4. Edge functions — active functions are declared and isolated from archives
  5. RLS behavior — 400/401 on unauthenticated access confirms security is active

The health check never mutates state. It is a pure observation mechanism.

8. Health Calculation

CCL health is the arithmetic mean of all subsystem health scores:

health = avg(identity.health, access.health, signal.health, relay.health, audit.health, integrity.health)

10. Why AUDIT Moved to CCL

AUDIT was previously a public module. It was moved into CCL for three reasons:

  1. Infrastructure nature — Compliance logging is infrastructure, not a user-facing capability. Users don't interact with AUDIT directly.
  2. Co-dependency — AUDIT depends on ACCESS (for authentication context) and IDENTITY (for actor attribution), both already in CCL.
  3. Consolidation — Having AUDIT separate created an artificial boundary between related infrastructure services.

The audit.* facade continues to work for backward compatibility.

  ├── identity/       — Session management, actor resolution
