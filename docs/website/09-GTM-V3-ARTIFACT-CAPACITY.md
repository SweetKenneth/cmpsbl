## Executive Summary

GTM v3 replaces feature-based monetization with an **Equal-Slot Artifact Capacity** model. The full substrate runtime is unified — every user runs every module. Plans differ only in:

1. **Artifact slot capacity** — how many packs can be activated (3 / 6 / 12)
2. **Memory depth** — standard, expanded, or dedicated partitions
3. **Deployment rights** — cloud-only vs. self-hosted (LNCHBL)
4. **Governance scope** — basic, advanced, or full authority

No module gating. No pack-level tier restrictions. No feature fragmentation.

Every artifact pack costs exactly **1 slot**. All 24 packs are visible to all users. Subscription capacity controls activation only.

## Strategic Domains

Artifact packs are organized under six category-defining domains:

### Memory & Continuity
Conventional AI forgets between sessions. The substrate remembers, contradicts, compresses, and evolves context across time — because cognition without continuity is noise.

### Coordination & Automation
Most automation stitches disconnected APIs. The substrate coordinates agents, workflows, and tasks within a single runtime — so orchestration emerges from architecture, not integration.

### Intelligence & Foresight
Static dashboards show what happened. The substrate synthesizes signals across domains, validates hypotheses, and projects forward — because intelligence is anticipation, not reporting.

### Resilience & Trust
Bolted-on security creates compliance theater. The substrate enforces trust, detects drift, and self-heals at the runtime level — because resilience must be structural, not cosmetic.

### Sovereignty & Deployment
Cloud-only platforms hold your infrastructure hostage. The substrate deploys anywhere — cloud, on-premise, air-gapped — because sovereignty means running what you own, where you choose.

### Perception & Interaction
Chatbots parse keywords. The substrate resolves intent, adapts personality, traverses knowledge, and routes data — because interaction is a cognitive act, not a string match.

## Artifact Pack Philosophy

### What Is an Artifact Pack?

A structured, versioned bundle of composed internal components that activates a specific capability domain. Packs are the **only purchasable unit** on the public surface.

### Equal-Slot Rule

Every pack costs exactly **1 slot**. No weighted slots. No variable pricing per pack. Simplicity enables clarity.

### Pack Rules

1. Each pack is **versioned** (v1.0, v1.1, etc.)
2. Each pack contains **composed internal components** (never raw engines or capabilities)
3. Each pack has a **defined use-case positioning** and documentation
4. Each pack contains **at least one substrate-native capability** — something impossible through API stitching
5. Internal taxonomy is **never exposed** — no internal mythology on public surfaces
6. All 24 packs are **visible to all users** — capacity controls activation only

## Baseline Technology Layer

### Definition

Baseline technology ships with every plan:

- All standard engines (31+ items)
- Common pipeline resolvers
- Utility capabilities
- Base project templates

These remain **fully operational** for all users. They are marked `visibility: 'baseline'` in the Quarry and are **not displayed** as purchasable items.

### Why

Prevents the Quarry from being flooded with low-density items. Keeps the public surface clean and focused on the 24 artifact packs only.

## Upgrade Psychology

### Behavioral Triggers

| Trigger | From → To | Signal |
|---------|-----------|--------|
| **Slot pressure** | Builder → Operator | User attempts to activate 4th pack |
| **Memory limitation** | Builder → Operator | Standard memory depth constrains project complexity |
| **Governance need** | Operator → Architect | Advanced governance insufficient for compliance requirements |
| **Deployment sovereignty** | Operator → Architect | Organization requires self-hosted or air-gapped operation |
| **Isolation requirement** | Operator → Architect | Multiple projects require dedicated memory partitions |
| **Scale demand** | Architect → Custom | 12 slots insufficient for organizational scope |

### Upgrade Flow Design

1. User hits natural capacity boundary
2. System surfaces contextual upgrade prompt (not generic upsell)
3. Upgrade unlocks additional slots — all packs remain visible
4. Zero migration friction — packs activate immediately on upgrade

## Quarry Governance Rules

### Public Surface

The Quarry's public-facing output is limited to:

1. 24 Structured Artifact Packs (equal-slot, no tier gating)
2. Strategic Domain framing
3. Capacity model (3 / 6 / 12)

### Internal Surface

The full Quarry (`/admin/quarry`) retains all assets with complete scoring, tier assignments, and visibility controls. Admin-only access.

### Visibility States

| State | Meaning |
|-------|---------|
| `hidden` | Internal only. Not shown anywhere. |
| `baseline` | Operational for all users. Not displayed as purchasable. |
| `tier_exposed` | Visible in admin context. May inform pack composition. |
| `public_curated` | Surfaced as artifact pack on /upgrade. |
