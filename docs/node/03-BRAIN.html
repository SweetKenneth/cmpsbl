Architecture

Hash-Embed-v1 Engine

BRAIN uses a proprietary hash-embed-v1 implementation: deterministic character-level FNV-1a hashing to produce 384-dimensional vectors. Zero external API calls. Same input always produces the same vector.

for each character c in input:
  hash = FNV-1a(c, position, seed)
  vector[hash % 384] += weight(c, position)
normalize(vector) → unit L2 norm

Trade Secrets

◆ Trade Secret #1 — Zero-Cost Embedding Strategy

The entire embedding pipeline runs client-side with zero API costs. By using deterministic hashing instead of transformer-based embeddings, BRAIN processes unlimited knowledge crystals without usage-based billing. The trade-off is lower semantic fidelity, compensated by higher crystal volume and multi-strategy recall.

◆ Trade Secret #2 — Confidence Decay Curves

Crystal confidence decays using a half-life model: confidence(t) = initial × 2^(-t / half_life). Half-lives vary: doctrine (90d), heuristic (30d), conversation (7d), error_pattern (14d). This ensures fresh knowledge outranks stale knowledge without manual curation.

◆ Trade Secret #3 — Drift Detection

BRAIN computes KL-divergence approximation between new data distributions and baseline. When drift_score > 0.15, a DRIFT_DETECTED signal is emitted to EVOLUTION. This is the substrate's early warning system for concept drift.

Staleness Detection

Embeddings older than 7 days are marked stale. Version bumps trigger automatic reindexing. Current version: 3.0.0. Staleness reports feed SEBA for prioritized maintenance.
