Architecture

Lineage Tracking

Every synthesized heuristic carries full provenance: parent IDs, generation depth, root sources, synthesis method, and per-generation confidence decay. MAX_GENERATION = 5 — no heuristic can be derived more than 5 levels deep to prevent semantic drift.

Dream Candidate Filter

Eligible Memories→ Gen < 5→ Not Active→ Conf > 0.3→ < 3 Syntheses→ Ranked Candidates

Synthesis Priority

priority = confidence×0.3 + access_freq×0.25 + recency×0.2 + uniqueness×0.25

Trade Secrets

◆ Trade Secret #1 — Generation Depth Limit

MAX_GENERATION = 5 prevents the "telephone game" effect. At generation 5, knowledge is "terminal" and must be validated by BRAIN before further use. This is the guardrail that keeps dream synthesis honest.

◆ Trade Secret #2 — Memory Weighting
weight = exp(-age/168) × log2(1+accessCount) × confidence²

Quadratic confidence emphasis means low-confidence memories have almost no influence on synthesis. The 7-day age decay ensures recency while logarithmic access scaling prevents popularity bias.

◆ Trade Secret #3 — Heuristic Auto-Flagging

Heuristics with counterExamples > 3 are automatically flagged for human review. This self-correcting mechanism prevents DREAM from propagating flawed patterns.

◆ Trade Secret #4 — Drift Pause

When the overall drift score exceeds 0.2 (computed as average confidence loss across generation transitions), DREAM pauses all synthesis until BRAIN revalidates the heuristic chain. This is the fail-safe against runaway semantic degradation.

Dream Consolidation Cycle

  1. Fetch eligible candidates (filterDreamCandidates)
  2. Sort by synthesis priority
  3. For each pair: check lineage, compute overlap (cosine > 0.5), synthesize
  4. Assign generation = max(parent_gen) + 1
  5. Compute confidence = min(parent_conf) × 0.85
  6. Store in MEMORY (WARM tier)
  7. Emit DREAM_SYNTHESIS_COMPLETE
